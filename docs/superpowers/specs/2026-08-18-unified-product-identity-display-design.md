# 全业务页面产品身份信息统一展示设计

## 目标

所有业务页面凡展示、搜索或选择产品时，统一完整显示以下三项身份信息，固定顺序为：

1. 产品编号
2. 客户料号
3. 型号

产品名称不再作为身份字段展示，也不用于替代型号。任何字段缺失时显示“—”。

## 展示规则

建立一个公共产品身份展示组件，接收 `productCode`、`customerPartNumber`、`model` 和紧凑度参数。

- 搜索下拉、详情卡片和编辑弹窗采用三行带标签布局。
- 紧凑表格采用一个“产品信息”单元格，按三行显示三个字段，避免额外增加表格宽度。
- 产品管理、库存管理等已经使用独立字段列的主列表继续保留独立列，但必须补齐缺少的客户料号列。
- 产品编号始终排在第一位。
- 三个字段允许自然换行和长单词断行，禁止省略号截断关键编号。
- 原生 `title` 或可访问文本包含三个字段的完整值，便于查看和辅助技术读取。

## 页面范围

本次统一改造覆盖所有现有业务页面中的产品展示区域，重点包括：

- 采购：采购复核、手工采购、采购收货、采购详情。
- 订单：新增/修改订单、库存分配、订单发货、订单详情。
- 库存：库存列表、新增/修改库存、库存相关选择框。
- 供应商与客户：供应产品、合同产品和产品搜索结果。
- 售后：退货商品、换货商品、退货收货、换货发出。
- 业务追踪与首页待办中的产品身份信息。
- 导入预览中存在产品记录的表格。

已有正确展示三个字段的区域改为复用公共组件或公共格式化函数；不改变其业务行为。

## 数据与接口

前端公共产品身份类型为：

```ts
export interface ProductIdentity {
  productCode?: string | null
  customerPartNumber?: string | null
  model?: string | null
}
```

后端查询必须为上述业务详情补齐 `productCode`、`customerPartNumber` 和 `model`。只扩展响应字段，不修改请求结构、数据库结构、产品唯一 ID 或任何库存与订单计算。

需要重点核查和补齐：

- 采购复核及采购收货明细。
- 订单库存分配与发货明细。
- 售后原商品、退货和换货明细。
- 订单及采购业务追踪明细。

## 组件边界

- `ProductIdentityDisplay` 只负责展示三个字段和可访问文本，不读取接口、不处理业务状态。
- 搜索选择组件继续负责交互，但选项文案通过统一格式化函数生成。
- 页面组件只传入当前记录的三个字段，不自行重复拼接显示字符串。
- 后端服务只负责查询并返回字段，不负责前端展示格式。

## 响应式布局

- 宽屏表格中的产品信息单元格提供足够基础宽度。
- 小窗口下三行纵向排列，长编号在字符边界处换行。
- 禁止 `text-overflow: ellipsis`、固定高度和 `overflow: hidden` 裁切产品身份组件。
- 表格行高随产品信息内容增长，不遮挡后续字段和操作按钮。

## 测试与验证

- 公共组件测试：顺序、缺失值、完整长编号和禁止产品名称。
- 页面组件测试：采购复核、收货、库存分配、发货、售后和业务追踪均包含三个身份字段。
- 后端查询/API 测试：相关明细响应均包含三个字段。
- 运行相关前后端测试和生产构建。
- 使用本地浏览器检查长产品编号、多产品订单和窄窗口，确认无省略号、裁切和字段错序。

## 非目标

- 不修改产品唯一编号规则。
- 不修改产品、订单、库存、采购或售后的业务计算。
- 不恢复或展示产品名称。
- 不调整数据库中的现有产品数据。
