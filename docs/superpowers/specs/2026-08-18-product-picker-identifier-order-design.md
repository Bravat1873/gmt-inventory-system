# 产品选择器标识展示与搜索设计

## 目标

统一订单管理与供应商管理中的产品选择体验。用户可以通过产品编号、客户料号或型号模糊搜索；所有相关搜索结果和已选产品信息均优先展示产品编号，避免重复客户料号造成误选。

## 范围

- 订单新增/修改弹窗中的订单明细产品选择器。
- 订单明细选中产品后的产品标识展示。
- 供应商新增/修改弹窗中的“供应产品”搜索结果。
- 供应商“供应产品”卡片中的产品标识展示。

不调整数据库字段、产品唯一 ID 规则、订单导入或供应商导入流程。

## 搜索规则

产品搜索文本由以下字段共同组成：

1. 产品编号 `productCode`
2. 客户料号 `customerPartNumber`
3. 型号 `model`

匹配继续使用现有模糊搜索能力。任一字段为空不影响其他字段参与搜索。

## 展示规则

搜索下拉中的每个产品采用三行结构，固定顺序为：

1. `产品编号：<值>`
2. `客户料号：<值>`
3. `型号：<值>`

缺失值显示 `—`。

订单明细选中产品后以及供应商“供应产品”卡片中，也使用相同字段顺序：产品编号、客户料号、型号。产品名称和物料规格可以保留在现有辅助信息区域，但不能取代这三个核心标识或排在产品编号之前。

## 组件方案

复用现有 `FuzzyPicker`，通过结构化产品选项标签实现多行展示，不另建第二套搜索组件。必要时为选项增加专用样式，使换行、间距、长文本和滚动行为与供应商弹窗现有交互一致。

## 边界情况

- 两个产品客户料号相同但产品编号不同：下拉中必须显示为两个独立选项，并可通过产品编号区分。
- 产品编号为空：显示 `产品编号：—`，仍可通过客户料号或型号搜索。
- 客户料号或型号为空：对应行显示 `—`。
- 长标识不得互相覆盖；允许自然换行或在现有弹窗宽度内完整展示。

## 验收与测试

- 自动化测试验证产品编号、客户料号、型号都进入搜索文本。
- 自动化测试验证下拉和已选产品区域的字段顺序为产品编号、客户料号、型号。
- 自动化测试验证重复客户料号的不同产品仍显示为独立选项。
- 运行订单弹窗、供应商弹窗相关测试和前端生产构建。
- 部署后在服务器验证页面加载和健康接口。
