# 产品编号后缀设计

## 目标

产品编号在现有自动生成的基础编码之后支持附加后缀，例如基础编码 `SXSEL_D61YZH70WPSE` 与后缀 `A` 组合为 `SXSEL_D61YZH70WPSE-A`。

## 编号规则

- 后缀作为独立字段保存，不直接混入品牌、型号等基础编码字段。
- 后缀为空时，产品编号保持现有基础编码，不追加连字符。
- 后缀非空时，由系统统一生成 `基础编码-后缀`，用户无需输入连字符。
- 后缀允许中文、英文、数字及符号，不限制业务长度；数据库字段使用可容纳长文本的类型。
- 修改品牌、型号、物料颜色、锁体类型、语言等基础字段时，重新计算基础编码并保留原后缀。
- 旧产品默认没有后缀，现有产品编号不做批量改写。

## 产品编号规则页面

- 在现有规则分类中加入“后缀”。
- 后缀规则项沿用现有规则的代码、名称、修改时间、删除和默认倒序展示方式。
- 后缀规则用于维护常用可选值，但不限制产品只能使用规则项。

## 产品新增与修改

- 产品表单增加“编码后缀”字段。
- 输入控件既可选择“后缀”规则中的常用值，也可直接输入任意自定义内容。
- 表单实时展示最终产品编号。
- 后端负责最终拼接、校验唯一性并保存，前端不作为编号生成的唯一可信来源。

## 数据与接口

- 产品表增加独立后缀字段。
- 产品查询、详情、新增和修改接口包含后缀字段。
- 编号规则接口增加后缀分类。
- 最终产品编号继续保存于现有产品编号字段，库存、订单、采购和售后仍通过该编号关联，无需改变关联方式。

## 错误处理

- 拼接后的最终产品编号若与其他产品重复，保存失败并提示产品编号已存在。
- 仅包含空白的后缀视为空后缀。
- 后缀首尾空白在保存前去除，内部字符原样保留。

## 测试

- 后端测试覆盖空后缀、自定义后缀、规则后缀、基础字段变化后保留后缀、最终编号重复。
- 前端测试覆盖规则选取、自定义输入、实时预览和编辑回显。
- 运行完整前端测试与构建、后端测试。
