# 产品复合唯一 ID 与三清单导入设计

## 目标

产品的业务唯一身份由系统生成的产品编号与客户料号共同决定。后端保存规范化后的拼接 ID，前端和接口仍分别展示产品编号与客户料号，不向用户暴露拼接字段。本次同时把产品工作簿导入范围从两张清单扩展为三张，并用用户提供的 `吉门第库存汇总表20260814(2)(1).xlsx` 全量替换产品资料。

受支持的产品清单为 `GMT库存产品清单`、`贝朗库存产品清单`、`STANLEY库存产品清单`；`库存数量`不作为产品主数据导入来源。

## 唯一 ID 规则

- 业务唯一 ID 格式为 `规范产品编号::规范客户料号`。
- 两部分拼接前去除首尾空格；判重使用统一大小写。
- 数据库保存拼接值，例如 `G_T5YZH60WPSC-M::G8T5VMHS02`。
- 产品编号继续由系统现有编码规则生成，Excel 的产品编号仅作参考。
- 客户料号保持原始展示值；规范化只用于底层唯一 ID 和匹配。
- 产品编号或客户料号为空时，该行校验失败。
- 数值主键 `sku.id` 继续承担内部外键关联；复合 ID 是业务唯一键，不替换数值主键。

## 数据模型与写入

- `sku` 增加非空业务唯一 ID 字段和唯一索引。
- 迁移根据现有 `product_code` 与 `customer_part_number` 回填；遇到空值或重复组合时明确失败，不静默合并或删除。
- 产品新增、编辑和 Excel 导入共用一个唯一 ID 生成器。
- 编辑产品编号规则选项或客户料号时重新生成并校验冲突。
- API 不要求前端提交唯一 ID。

## 三清单导入

- 解析器固定读取三张产品清单，缺少任一张时预览失败并指出表名。
- 三表共用表头、说明行和业务行识别规则。
- 正式行必须有客户料号，并能由当前规则生成产品编号。
- Excel 产品编号和物料规格继续由系统忽略并重新生成。
- 预览冲突键改为复合唯一 ID：相同产品编号可对应不同客户料号，只有相同组合才冲突。
- 冲突仍需明确保留或跳过；提交时重新计算产品编号、规则指纹与复合 ID。

## 全量替换

- 沿用管理员权限、配置开关和单事务的产品全量替换流程。
- 所有错误行和未处理冲突清零后才允许提交。
- 清理范围、外键顺序和回滚行为保持现有实现。
- 插入时同时保存产品编号、客户料号和复合 ID；供应商报价沿用现有规则。
- 产品清单内库存列及独立 `库存数量` 表不在产品主数据步骤写入库存，库存继续走独立导入批次。

## 前端与接口

- 产品列表、详情、搜索结果及各产品选择器继续分别显示产品编号与客户料号。
- 拼接 ID 不新增可见列，不要求用户输入。
- 冲突文案表述为“产品编号 + 客户料号组合重复”。
- 搜索仍按客户料号、型号和产品编号进行，不新增拼接字符串搜索。

## 错误处理

- 缺少任一产品清单时整次预览失败。
- 客户料号为空、编号无法生成、供应商匹配失败或数字字段非法时按行报错。
- 同产品编号不同客户料号可共存；相同组合形成冲突。
- 手工新增或编辑产生重复组合时返回明确业务错误。
- 替换过程任一失败均回滚，保留原数据。

## 测试与验收

- 测试唯一 ID 拼接、去空格、统一大小写、缺失字段与分隔符。
- 测试迁移字段、唯一索引、安全回填与重复失败。
- 测试手工新增和编辑生成复合 ID 并拒绝冲突。
- 测试三表解析、说明行忽略、缺表报错和有效行数。
- 测试同编号不同客户料号可共存，相同组合形成冲突。
- 测试三表全量写入、复合 ID、供应商关系和事务回滚。
- 前端测试确认两字段仍分别显示，界面不出现内部拼接 ID。
- 使用指定工作簿预览，错误与未处理冲突为零后才提交。
- 提交后核对三表有效行数、产品总数、唯一性和供应商报价，并分别抽查 GMT、贝朗、STANLEY 产品。

## 非目标

- 不用业务字符串替换数据库数值主键或外键。
- 不展示或编辑拼接 ID。
- 不修改产品编号生成规则。
- 不把 `库存数量` 工作表混入产品主数据解析。
- 不修改原始 Excel 文件。
