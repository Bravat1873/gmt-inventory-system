# 订单发货数量口径统一与锁定库存释放设计

## 目标

统一订单业务全景、手动分配库存和确认发货三个界面的数量字段，消除“已发货”“剩余”“锁定”等不同叫法造成的歧义；同时保证每次发货都从该订单已锁定的库存中扣减，并同步释放相同数量的订单锁定记录。

## 统一字段与公式

三个界面统一使用以下中文名称：

| 字段 | 业务含义 | 公式或来源 |
| --- | --- | --- |
| 订单数量 | 客户下单数量 | `sales_order_item.quantity` |
| 已发货数量 | 截至当前累计发出的数量 | `sales_order_item.shipped_quantity` |
| 未发货数量 | 订单尚未发出的数量 | 订单数量 − 已发货数量 |
| 本单锁定数量 | 当前为该订单保留、尚未发出的实际库存 | `sales_order_item.locked_quantity` |
| 缺货数量 | 未发货数量中尚未锁定的数量 | `max(0, 未发货数量 − 本单锁定数量)` |
| 实际库存数量 | 仓库当前实物数量 | `inventory_balance.actual_quantity` |
| 未锁定库存数量 | 实际库存中未被任何订单占用的数量 | 实际库存数量 − 库存总锁定数量 |
| 本次发货数量 | 本次操作准备发出的数量 | 用户输入 |
| 发货后未发货数量 | 本次发货完成后的订单欠交数量 | 未发货数量 − 本次发货数量 |

不再在这三个流程中使用“订单数”“累计已发”“当前锁定”“可用库存”“发货后剩余”等简写。

## 发货事务规则

每条订单明细只允许从“本单锁定数量”发货，本次发货数量不得超过以下两者中的较小值：

1. 当前未发货数量；
2. 当前本单锁定数量。

一次成功发货必须在同一个数据库事务中同步完成：

1. `sales_order_item.shipped_quantity += 本次发货数量`；
2. `sales_order_item.locked_quantity -= 本次发货数量`；
3. `inventory_balance.actual_quantity -= 本次发货数量`；
4. `inventory_balance.locked_quantity -= 本次发货数量`；
5. 重新计算 `sales_order_item.uncovered_quantity = max(0, 未发货数量 − 本单锁定数量)`；
6. 写入发货单、发货明细和库存流水。

任何一步失败都回滚，避免订单锁定数量与库存总锁定数量不一致。分批发货和整单发货共用同一套扣减语义。历史已产生的不一致数据不在本次自动批量修改；新逻辑上线后，后续发货将保持一致。

示例：订单数量 800、已发货数量 400、本单锁定数量 500，本次发货 400。完成后已发货数量为 800、本单锁定数量为 100、未发货数量为 0、缺货数量为 0。剩余锁定 100 属于超出未发货数量的不合理历史状态，发货事务应将其释放，使最终本单锁定数量为 0、库存总锁定数量也额外释放 100。

## 界面调整

### 订单业务全景

订单明细表显示：订单数量、已发货数量、未发货数量、本单锁定数量、缺货数量、含税单价、未锁定库存数量。库存锁定轨迹中的“实际、锁定”改为“实际库存数量、本单锁定数量”。

### 手动分配库存

表头显示：产品、订单数量、已发货数量、实际库存数量、本单锁定数量、未锁定库存数量、分配给客户。说明文字继续明确减少分配会立即释放为未锁定库存。

### 确认发货

顶部汇总显示：订单数量、已发货数量、本次发货数量。明细显示：订单数量、已发货数量、本单锁定数量、本次发货数量、发货后未发货数量、未锁定库存数量。

## 异常处理

- 本次发货数量超过本单锁定数量时，阻止提交并提示先分配库存。
- 库存总锁定数量或实际库存数量不足时，事务回滚并提示库存数据异常。
- 发货完成后若订单不再有未发货数量，自动释放该订单明细遗留的锁定数量，防止已完成订单继续占用库存。
- 已有发货记录的订单仍禁止手动重新分配库存，避免追溯历史时改变已执行分配。

## 测试设计

1. 后端回归测试先复现分批发货后订单明细锁定数量未减少的问题。
2. 验证分批发货同步减少订单锁定与库存总锁定，并正确重算未发货和缺货数量。
3. 验证完成发货后自动释放多余锁定数量。
4. 验证整单发货同样将订单明细锁定数量归零。
5. 验证超过本单锁定数量的发货被拒绝且事务不产生部分写入。
6. 前端组件测试验证三个界面只显示统一名称，不再出现旧名称。
7. 执行完整后端、前端测试和生产构建，并在本地 Docker 中验证真实 MySQL 与页面流程。
