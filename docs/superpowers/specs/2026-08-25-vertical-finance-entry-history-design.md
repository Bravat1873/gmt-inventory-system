# 上下式资金与发票登记界面设计

## 目标

将发票、登记付款和登记收款弹窗改为上下式布局。打开弹窗时先显示历史记录及其复核状态，再在下方录入本次数据，方便在提交前核对已通过、待复核和已驳回的记录。

同时收紧所有管理列表的右侧操作列，使“操作”表头和行内按钮处于同一紧凑列，不再因固定的过大列宽在表格中间留下空白。

## 弹窗结构

三种弹窗共享以下视觉顺序：

1. 标题区保留关联业务单号与当前业务说明。
2. 顶部为“历史记录及复核状态”，显示记录数量；历史为空时显示明确空状态。
3. 中部或下部为“本次登记”，保留原有的金额预填、输入校验、保存和取消操作。
4. 底部操作按钮保持右对齐，状态标签继续区分待复核、已通过和已驳回。

历史表格在弹窗内独立横向滚动，避免字段较多时压缩金额、状态和备注；历史区域高度受限，确保本次登记表单无需整页滚动即可看到。

## 各类历史记录

- 发票：原发票号码、财务确认号码、日期、原金额、确认金额、复核状态、复核备注和删除操作。
- 付款：登记金额、财务确认金额、付款方式、登记时间、复核状态和备注。
- 收款：登记金额、财务确认金额、收款方式、登记时间、复核状态和备注。

付款和收款历史复用现有按业务单据读取的资金记录接口；仅显示当前采购单或销售订单的数据。提交登记后重新加载历史记录，以显示新建的待复核记录。

## 列表操作列

- `ModuleListPage` 继续让操作列固定在右侧，表头与单元格使用同一个操作列类名和右侧边界。
- 宽度按模块的最大可见按钮组合设置为紧凑宽度，不再为每个模块预留 420 至 540 像素。
- 订单、采购、财务及其他列表统一使用此实现；操作按钮保留单行显示，内容不足时不扩大列宽。

## 兼容性与测试

- 不改变付款、收款、发票保存接口和财务复核规则。
- 发票默认金额仍取最近一笔收款或付款的原始金额，用户仍可修改。
- 组件测试覆盖三种弹窗的历史区在表单之前渲染、历史状态展示和保存后刷新。
- 列表测试覆盖订单、采购和财务的紧凑右侧操作表头与按钮列。
