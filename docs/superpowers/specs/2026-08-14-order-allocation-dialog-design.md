# 手动分配库存弹窗视觉统一设计

## 目标

将订单管理中的“手动分配库存”弹窗调整为与系统现有业务弹窗一致的视觉结构，改善内容贴边、信息层级不足和底部操作区松散的问题，同时保持现有库存分配逻辑不变。

## 现状与根因

当前弹窗虽然使用了通用 `dialog-card`，但正文说明、表格和底部按钮直接排列在卡片根节点下，没有独立内容容器和专用布局样式。全局表格样式因此直接作用于弹窗内容，造成说明文字贴边、表格缺少边界、底部操作栏没有稳定分隔，与“确认发货”等弹窗不一致。

## 设计方案

### 弹窗结构

- 弹窗宽度调整为适合七列表格的约 900px，并受视口宽度限制。
- 卡片采用纵向弹性布局，标题栏、正文和底部操作栏相互独立。
- 标题栏保持“手动分配库存”和右侧“关闭”，补充无障碍标题关联。
- 正文区域可滚动，避免内容较多时把底部按钮推离视口。

### 说明提示

- 将现有说明文字放入浅灰色提示区域。
- 使用较小字号和舒适行高，明确表达减少分配数量会释放未锁定库存。
- 提示区域与表格之间保持统一间距。

### 分配表格

- 表格外增加边框、圆角和独立横向滚动容器。
- 表头使用浅灰背景，数值列保持紧凑且不换行。
- 产品列提供更宽空间，物料编号与产品名称允许合理截断。
- 数量输入框使用统一高度、边框和聚焦状态。
- 窄屏时只在表格容器内部横向滚动，不扩大弹窗或页面宽度。

### 底部操作栏

- 底部操作栏增加顶部边框、白色背景和统一内边距。
- 右侧依次显示“取消操作”和“确认分配”。
- 保存过程中禁用关闭和操作按钮，保持现有交互语义。
- 错误提示放在正文区域、表格下方，不改变底部栏位置。

## 功能边界

- 不修改自动锁定、手动分配、库存释放或接口请求逻辑。
- 不改变各数量字段含义和校验范围。
- 不引入新的组件库或全局弹窗重构。
- 遮罩仍不可通过点击关闭，只保留明确的关闭和取消按钮。

## 验证

- 增加组件测试，验证标准标题、提示区、表格容器和底部操作栏结构。
- 保留并运行现有库存分配交互测试。
- 运行前端相关测试和生产构建。
- 在桌面宽度与窄屏宽度下检查弹窗不越界，表格仅在内部滚动。
