# 供应商产品空采购字段与采购提醒布局设计

## 目标

1. 供应商修改窗口显示该供应商已经关联的全部产品。
2. 新增供应商产品关系时，采购单价、最小起购量、交货天数默认均为空，由用户后续手工填写。
3. 任一采购字段为空时，该关系不得被视为有效采购信息，也不得参与采购建议生成。
4. 修复采购管理顶部“缺货产品未配置有效供应商采购信息”展开内容被裁切的问题。

## 数据语义

- 采购单价、最小起购量、交货天数使用真正的可空值，不用 `0` 或 `1` 伪装“未填写”。
- 已有非空历史值保持不变；迁移不清空现有数据。
- 新增关系不填写上述字段时保存为 `NULL`。
- 后续在供应商修改窗口填写后，按原有修改流程保存。

## 供应商产品展示

- 打开供应商修改窗口时，后端按供应商 ID 返回全部产品关系及产品基础信息。
- 表格展示产品、采购单价、最小起购量、交货天数、修改时间和操作。
- 空字段显示为空输入框，不显示 `0`、`1` 或破折号默认值。
- 产品搜索与新增关系保持现有交互；保存供应商时一并保存新增或修改的关系。

## 采购有效性

- 有效采购关系必须同时具备：采购单价、最小起购量、交货天数。
- 任一字段为空时，采购管理继续将该产品列入“未配置有效供应商采购信息”提醒。
- 采购建议生成忽略不完整关系，避免用默认值误生成采购单。

## 布局修复

- `.procurement-configuration-alert` 设为不可被父级 Flex 容器压缩。
- 展开提醒完整显示产品信息与“前往供应商管理”按钮。
- 下方采购列表继续承担剩余空间滚动，不扩大页面整体高度。
- 保留现有圆角和 `overflow` 视觉效果。

## 兼容与错误处理

- 数据迁移只放宽字段为空能力，不更改已有值。
- API 明确区分 `null` 与合法数值；负数继续拒绝。
- 保存失败时保留用户输入并显示后端错误。
- 服务器产品全量替换属于独立高风险操作，不包含在本次界面与空值修改中。

## 验证

- 后端：新增关系空值保存、已有值保留、采购有效性过滤、后续补填。
- 前端：供应商关系加载与显示、三个字段空输入、修改保存。
- 布局：小高度窗口展开提醒不裁切，按钮完整可见，下方表格仍滚动。
- 回归：供应商、采购管理相关测试、前端全量测试与构建。
