# 动态库存地点锁定分配设计

## 目标

精简库存管理主表，将固定的五个地点锁定数量移入“修改库存”弹窗，并改为可扩展的动态列表。删除功能重复且信息单薄的“查看明细”入口，用户通过“修改”查看并维护完整库存资料。

## 页面设计

- 库存主表保留 SKU、产品信息、实际库存、可用库存、库龄、已锁定总量、在途数量、供应商、备注和修改时间。
- 主表删除“铭爱钧乔、博乐龙米、老挝、贝朗、马来西亚”五个固定列。
- 库存行操作仅保留“修改”，删除“查看明细”按钮及对应入/出库明细弹窗入口。
- 修改库存弹窗增加“地点锁定分配”区，每行包含地点名称与锁定数量，并支持新增、删除地点。
- 地点为空、地点重复、数量非非负整数时禁止保存。

## 数据设计

- API 使用 `lockedAllocations: Array<{ lockSource: string; quantity: number }>` 表示地点分配，不再暴露五个固定地点字段。
- 读取库存详情时，从 `inventory_locked_allocation` 按库存记录读取所有分配并返回数组。
- 保存库存时，在同一事务内校验并替换该库存记录的地点分配。
- `locked_quantity` 继续作为锁定总量。地点分配数量合计不得超过锁定总量；允许小于锁定总量，以兼容订单自动锁定等没有地点标签的锁定来源。
- 删除地点行等价于删除对应 `inventory_locked_allocation` 记录。

## 兼容与错误处理

- 现有五个地点数据无需迁移，读取后自然显示为动态行。
- 后端拒绝重复地点、空地点、负数或小数数量，以及地点分配合计超过锁定总量的请求。
- 并发更新继续使用库存记录版本号，版本冲突提示用户重新打开。

## 测试与验收

- 后端覆盖动态读取、保存新地点、删除地点、重复地点和合计超限校验。
- 前端覆盖库存主表不再显示固定地点列与“查看明细”，修改弹窗能新增、修改、删除地点分配并提交数组。
