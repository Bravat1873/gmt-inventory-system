# 产品多供应商报价设计

## 目标

允许同一个产品同时关联多家供应商。供应商管理中维护产品关系和采购报价后，产品管理实时展示该产品的全部供应商报价。

## 产品管理展示

产品管理列表删除以下三列：

- 成本单价（含税）
- 转厂价格
- 差异：转厂价－原成本

保留“销售最小起订量”。新增“供应商报价”列，每个关联供应商单独一行，格式为“供应商名称：采购价格”。没有有效供应商时显示“—”。

产品原有成本价和转厂价格数据及后台字段继续保留，仅从产品管理列表隐藏，避免影响历史采购、导入和其他业务计算。

## 数据关系

`sku_supplier_config` 从“一个产品只能关联一个供应商”调整为“同一产品和同一供应商组合不能重复”。一个供应商仍可关联多个产品，一个产品也可关联多个供应商。

迁移只调整唯一约束，不删除现有关系或报价。有效关系必须同时满足关系、产品和供应商均为启用状态。

## 保存与同步

供应商管理保存时，只更新当前供应商自己的产品关系：

- 新增产品：新增或重新启用当前供应商与产品的关系。
- 修改报价、采购最小起订量或交货天数：只修改该组合。
- 删除产品：只停用当前供应商与该产品的关系，不影响其他供应商。

产品管理不复制供应商名称，而是在查询时从关系表实时汇总，因此供应商改名、增删产品或调整报价后，刷新产品管理即可看到最新结果。

## 接口与兼容

产品列表新增 `supplierQuotes`，每项包含供应商 ID、名称和采购价格。原有单供应商字段暂时保留，兼容可能存在的调用方，但产品列表 UI 使用新数组渲染。

采购选供应商继续读取产品的所有有效供应商，并显示各自采购价格、采购最小起订量和交货天数。

## 验证

- 数据库迁移后现有关系和数据数量不变。
- 同一产品可保存两个不同供应商关系。
- 同一供应商与同一产品不会产生重复有效关系。
- 删除一个供应商的产品关系不会删除另一供应商关系。
- 产品列表展示全部供应商报价，并隐藏指定的三个价格列。
- 后端完整测试、前端完整测试和生产构建通过。
- 本地 Docker 重建后，通过实际页面/API验证新列表。
