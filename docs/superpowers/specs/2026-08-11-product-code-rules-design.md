# 产品编号与编码规则维护设计

## 目标

产品管理不再使用可重复的客户编号作为系统产品标识。系统新增自动生成且全局唯一的产品编号，并提供可由所有登录用户维护的编码映射页面。产品编号示例为 `BR_P90HGT60WPZE`。

同时将全系统界面中的“物料编号”统一改称“客户编号”，并保证现有订单、采购、库存和供应商关联不受影响。

## 字段定义

- `产品编号`：系统内部唯一编号，自动生成，不允许手工输入。
- `客户编号`：原物料编号，可以为空、可以重复，不作为关联键。
- `品牌`：产品品牌，同时决定产品编号前缀。
- `系列`：原“型号”字段的业务名称。
- `主体颜色`、`锁体类型`、`联网方式`、`销售渠道`、`运营主体`、`语言`：产品编号的其余组成项。

订单、采购、库存等业务记录继续通过产品数据库 ID 关联，不通过产品编号或客户编号建立外键关系。

## 产品编号规则

正式产品编号按以下顺序拼接：

```text
品牌代码_系列代码颜色代码锁体代码联网代码渠道代码运营主体代码语言代码
```

例如：

```text
BR_P90HGT60WPZE
```

其含义为：

- `BR`：STANLEY 品牌前缀
- `P90`：P90 系列
- `HGT`：红钻铜
- `60`：6068 锁体
- `W`：WiFi
- `P`：平面销售渠道
- `Z`：珠海运营主体
- `E`：英文版

品牌代码与其余代码之间固定使用一个下划线，其他代码直接连接。编码统一转为大写，只允许英文字母和数字。

品牌、系列、主体颜色、锁体类型、联网方式、销售渠道、运营主体和语言共 8 项全部必填。任一项缺失时不能生成正式编号，页面显示“请补齐产品编码信息”。正式编号由后端生成并校验，前端只提供实时预览。

## 初始映射

系统初始化图片中给出的映射，包括：

- 系列：P90、P50、S70、S50、F70、F50、D51
- 主体颜色：HGT=红钻铜、FGJ=富贵金、YZH=宇宙黑、PBY=瀑布银、XKH=星空黑、BSL=宝石蓝
- 锁体类型：60=6068、70=7068、00=直舌、01=钩舌
- 联网方式：W=WiFi、B=Bluetooth、C=Cat.1/4G、N=NB-IoT、O=单机、M=MATTER
- 销售渠道：P=平面、G=工程、E=电商、K=商超、D=东铁专供
- 运营主体：Z=珠海、S=深圳、G=广州
- 语言：E=英文版、C=中文版、S=西班牙语
- 品牌：STANLEY=BR

## 编码规则维护页面

产品管理页面右上角增加“编码规则”入口。维护页面按品牌、系列、主体颜色、锁体类型、联网方式、销售渠道、运营主体和语言分类切换。

每条规则包含：

- 显示名称
- 编码
- 启用状态
- 排序序号
- 备注

第一阶段所有登录用户都可以查看、新增、修改、停用和排序规则。

同一分类内的编码忽略大小写后必须唯一。已被产品引用的规则不能删除，也不能修改编码，只能修改名称、排序、备注和启用状态；尚未被产品使用的规则可以修改编码。停用规则不影响历史产品展示，但新增或编辑产品时不能再选择。

## 产品页面

产品列表和编辑表单增加产品编号、客户编号、品牌、系列、主体颜色、锁体类型、联网方式、销售渠道、运营主体和语言。

新增或编辑产品时，8 个编码属性使用启用规则的下拉选项。选择变化后立即预览产品编号，最终编号仍由后端重新计算。编号重复时禁止保存并明确提示冲突编号。

产品编号不可直接输入。客户编号可以为空和重复。

## 全系统显示与搜索

产品、订单、采购、库存、供应商产品和业务轨迹页面中的“物料编号”统一改称“客户编号”。产品选择器优先显示产品编号，并辅助显示客户编号、品牌、系列和产品名称。

产品搜索同时匹配：

- 产品编号
- 客户编号
- 品牌
- 系列
- 产品名称或规格

业务明细应显示产品编号，避免使用可能重复的客户编号区分产品。

## 数据库与迁移

产品表新增唯一且非空的产品编号字段，并新增 8 个编码规则引用。原 `sku_code` 字段继续保存客户编号，但取消唯一约束并允许为空。为降低改造风险，数据库物理列名可以保留，API 和界面语义统一调整为客户编号。

新增编码规则表，分类和编码组成忽略大小写的唯一约束。产品通过规则 ID 引用映射项，同时保存生成后的产品编号快照。

迁移现有产品时，按稳定的产品 ID 顺序生成：

```text
OLD_000001
OLD_000002
...
```

过渡编号保持唯一。现有产品编辑时，如果 8 项尚未补齐则继续保留原过渡编号；全部补齐并保存后替换为正式编号。

修改规则显示名称不改变已有产品编号。已引用规则禁止改码，从而保证产品编号含义与历史记录稳定。

## 导入兼容

成本和库存等既有导入同时接受“物料编号”和“客户编号”表头，两者都写入客户编号字段，保证旧模板继续可用。

新模板可包含 8 个编码属性列。全部属性能够匹配启用规则时生成正式产品编号；缺少属性的旧格式记录生成唯一的 `OLD_******` 过渡编号。

映射不存在、映射已停用、正式产品编号重复或同批次生成重复编号时，在预览中标记为错误并禁止提交。

导入后的产品匹配不能仅依赖客户编号，因为客户编号允许重复。优先按产品编号匹配；没有正式产品编号的旧导入流程必须使用明确且不会误合并的匹配策略，无法唯一确定时要求用户处理冲突。

## 一致性与错误处理

- 产品编号在后端统一生成，保存产品和生成编号处于同一事务。
- 数据库唯一约束作为并发情况下的最终防线。
- 客户编号重复不视为错误。
- 引用中的规则被停用后，历史产品仍可读取和展示。
- 删除已引用规则返回明确的业务错误，界面引导用户改为停用。
- 编码输入自动去除首尾空格并转换为大写，非法字符在保存前提示。

## 验证范围

- 编码拼接顺序、下划线和自动大写
- 8 项必填与编号预览
- 产品编号重复及并发保存
- 客户编号为空和重复
- 规则分类唯一性、停用、引用后禁止删除或改码
- 历史产品 `OLD_******` 迁移及后续转正式编号
- 新旧 Excel 表头兼容和导入冲突预览
- 产品、订单、采购、库存、供应商和业务轨迹的统一名称、显示与搜索
- 所有登录用户对编码规则的第一阶段读写权限


## 入户门扩展

产品新增必填的产品类别：`SMART_LOCK`（智能锁）和 `ENTRY_DOOR`（入户门）。现有产品迁移为 `UNCLASSIFIED` 并保留 `OLD_******`；新增产品不能选择未分类。

入户门编号格式为 `品牌代码_成品型号代码安全等级代码主基材料代码厚度代码花色代码`。例如 `BR_MJ3080A` 表示 STANLEY、单开门、甲级、304 不锈钢、80mm、花色 A。品牌及 5 项入户门属性全部必填。

入户门初始映射：

- 成品型号：N=对开门、K=子母门、M=单开门、L=连套门（一门一套）
- 安全等级：J=甲、Y=乙、B=丙、D=丁、T=特级加强
- 主基材料：1=钢板/锌钢板、2=2.0不锈铁、3=304不锈钢、4=316不锈钢、5=铜板/锌铜板、6=木板、7=岩板、8=铝合金、9=特殊板材
- 成品厚度：050、055、080、085、100、120（单位 mm）
- 花色：A 至 F，初始显示名称为“花色A”至“花色F”

编码规则维护页面分为通用、智能锁和入户门：通用维护品牌；智能锁维护原 7 类专属属性；入户门维护成品型号、安全等级、主基材料、成品厚度和花色。所有登录用户继续拥有读写权限。
