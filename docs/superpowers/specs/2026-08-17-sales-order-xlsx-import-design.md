# 销售订单 XLSX 批量导入设计

## 目标

在订单管理中增加 XLSX 批量导入能力，并提供可直接填写的标准模板。导入使用客户编码唯一匹配客户、产品编号唯一匹配产品；同一个外部订单号的多行明细合并为一张销售订单。同步修复历史展示问题：系统中所有面向用户的“物料编号”统一改称“客户料号”，但数据库和接口内部字段名保持不变，避免破坏既有数据和接口。

## 导入模型

采用单工作表、扁平明细结构。一行代表一个订单产品明细，订单级字段在每一行重复填写。同一外部订单号的行组成一个订单，按工作表行号生成订单明细顺序。

### 必填列

| 列名 | 规则 |
| --- | --- |
| 外部订单号 | 同一文件内作为订单分组键；已有正式订单使用该编号时整单报错 |
| 客户编码 | 必须唯一匹配一个已启用客户 |
| 订单日期 | 合法日期 |
| 订单类型 | 工程订单、零售订单、前置订单之一 |
| 销售员 | 非空 |
| 产品编号 | 必须唯一匹配一个已启用产品 |
| 订单数量 | 正整数，且不得低于产品销售最小起订量 |
| 含税单价 | 大于等于零，模板不以空白自动推断价格 |

### 可选列

订单状态、客户料号、业务联系人、业务联系电话、订单联系人、订单联系电话、财务联系人、财务联系电话、收货地址、收货联系人、收货联系电话、发货方式、订单备注。

“客户料号”只用于展示和辅助核对，不参与产品匹配。若填写且与产品档案中的客户料号不一致，预览时给出错误，防止选错产品。

## 分组与一致性

同一外部订单号下，客户编码、订单日期、订单类型、销售员、订单状态、联系人、收货信息、发货方式和订单备注必须一致；不一致时整组不得提交。一个外部订单号至少包含一条有效产品明细，同一订单内允许多个不同产品。

## 状态与库存

订单状态可填写“草稿”或“正式订单”。模板默认值为“正式订单”。

- 草稿映射为 `DRAFT`，不分配库存。
- 正式订单映射为 `PENDING_CUSTOMER_PAYMENT`，复用现有订单创建逻辑分配库存、生成锁定数量和采购缺口。

客户余额继续只用于显示和提醒，不因导入订单自动扣减；资金扣减仍走登记收款流程。

## 预览、错误与提交

上传后先进入预览，不自动提交。预览按订单分组展示，并统计订单数、明细数、有效数和错误数。以下情况禁止提交：

- 客户编码不存在、重复或客户不可用；
- 产品编号不存在、重复或产品不可用；
- 同一外部订单号的订单级字段不一致；
- 外部订单号已被现有订单使用；
- 数量、价格、日期、订单类型或状态不合法；
- 填写的客户料号与产品档案不一致；
- 正式订单低于产品销售最小起订量。

提交按订单事务执行：一张订单及其明细要么全部成功，要么全部回滚。不同订单可分别报告成功或失败，避免一个错误订单覆盖其他错误信息。重复提交同一已提交批次应被拒绝。

## 模板

生成 `销售订单批量导入模板.xlsx`，包含：

1. `订单导入`：表头、两张示例订单、数据验证下拉、日期和金额格式、冻结表头、筛选和填写提示。
2. `填写说明`：字段解释、必填规则、分组规则、状态与库存锁定说明、错误示例。

模板中的示例产品编号和客户编码只作格式示意，不代表系统真实数据；用户应替换后再导入。

## 界面与权限

订单管理增加“导入订单”入口，沿用现有导入弹窗的预览、错误提示和确认交互。允许当前具备订单新增权限的管理员和订单角色使用；后端再次校验权限，不能只依赖前端隐藏。

## “物料编号”历史用词修复

全量扫描前端标签、占位符、校验提示、业务追溯、客户合同、供应商产品、订单、库存和采购提示，以及后端面向用户的错误信息和 XLSX 表头：

- 原“物料编号”统一显示为“客户料号”；
- 产品的唯一系统标识始终显示为“产品编号”；
- 不修改 `skuCode` 等内部字段名，也不进行数据库字段迁移。

现有历史 XLSX 成本和库存导入可兼容旧表头“物料编号”，同时接受新表头“客户料号”，避免旧文件失效；新模板只输出“客户料号”。

## 验证

- 后端解析、分组、唯一匹配、重复订单、字段一致性、事务回滚和库存锁定测试；
- 前端入口权限、预览、错误禁用、确认提交和用词回归测试；
- XLSX 模板结构、数据验证、格式、示例和视觉渲染检查；
- 在本地开发库导入包含一张多明细正式订单和一张草稿订单的测试文件，核对正式订单增加锁定、草稿不增加锁定、客户余额不变。
