# 简洁发货弹窗设计

## 目标

将发货弹窗改成紧凑、易读的一屏操作界面，减少说明文字、边框和横向表格负担，同时保留分批地址、库存校验与历史追溯能力。

## 信息结构

- 顶部只显示“订单发货”、订单编号和关闭按钮，不再展示累计数量的长说明。
- 摘要区并排显示订单总数、累计已发和本次待发三个数字。
- 收货地址使用紧凑输入区，默认带出订单地址，允许本批修改；提供“使用订单地址”快捷按钮。
- 历史发货默认收起，只显示批次数量；点击后展开日期、数量和地址列表。
- 产品明细由宽表格改为紧凑行卡片：产品信息、订单数量、累计已发、本次发货输入和发货后剩余数量。
- 底部操作区固定显示本次发货合计，右侧为取消和确认发货按钮。

## 数量交互

- 用户输入“本次发货数量”，不再直接编辑累计已发数量。
- 页面提交时将原累计已发数量与本次输入相加，转换为现有后端要求的累计值。
- 本次发货默认值为 0，必须是非负整数，且不能超过本单已备货量或订单剩余数量。
- 发货后剩余数量实时计算为 `订单数量 - 累计已发 - 本次发货`。
- 所有行本次数量均为 0 时，确认按钮禁用，不发送空操作。
- 当前功能只处理正向发货；既有的累计数量调减能力不放在简洁发货弹窗中。

## 地址与历史

- 地址在本次发货数量大于 0 时必填，空白地址阻止提交并提示。
- “使用订单地址”恢复订单默认地址；订单无默认地址时按钮禁用。
- 历史折叠标题显示“历史发货（N 批）”，使用原生按钮维护可访问的展开状态。
- 展开后每批显示中文日期时间、“N 件”和完整收货地址；保留现有可访问标签。

## 视觉与响应式

- 延续系统黑、白、浅灰风格，使用少量浅灰背景分组，圆角与现有客户合同卡片保持一致。
- 产品行不使用纵向表格线，数量信息采用小标签，突出“本次发货”输入框。
- 桌面端产品信息和数量横向排列；窄屏自动改为上下布局，按钮保持可点击尺寸。
- 弹窗主体限制高度并只让内容区滚动，底部确认区域始终可见。

## 错误处理与测试

- 保持后端库存、备货量和地址校验不变。
- 前端测试覆盖：默认本次数量为 0、累计值转换、最大数量、实时合计与剩余量、空操作禁用、地址恢复、历史默认收起及展开、窄屏结构类名。
- 完成后运行前端完整测试和生产构建；本次仅修改前端，不需要数据库迁移或后端重启。
