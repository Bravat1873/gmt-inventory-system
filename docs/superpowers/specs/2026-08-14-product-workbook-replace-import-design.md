# 双产品表全量替换导入设计

## 目标

支持从“吉门第库存汇总表”中的两个产品清单工作表全量替换开发环境产品数据。导入以产品编号为唯一标识，缺失字段按空值或数据库默认值保存，重复编号必须由导入人员明确选择覆盖或跳过后才能提交。

本次源文件包含：

- `GMT库存产品清单`：8 条有效产品记录。
- `贝朗库存产品清单`：9 条有效产品记录。
- 两表合计17条记录、17个唯一产品编号，当前文件不存在重复编号。
- `库存数量`不属于本次产品资料导入范围。

## 导入入口与流程

沿用产品管理的“导入产品”入口，增加“双产品表全量替换”能力：

1. 用户上传 Excel。
2. 后端只解析两个指定产品清单工作表，自动跳过表头后的编码说明行和空行。
3. 系统生成导入预览，显示来源工作表、Excel行号、产品编号、核心产品字段、供应商和校验状态。
4. 重复产品编号显示为冲突行，导入人员必须逐条选择“覆盖”或“跳过”。
5. 普通错误行必须修正或跳过；存在未处理冲突时禁止提交。
6. 用户再次确认“全量替换”后，后端在单个事务中清理开发数据并导入预览结果。
7. 任一删除或写入失败时整个事务回滚，原数据库保持不变。

## 数据行识别

- 第一行作为字段标题。
- 标题之后的编码说明行通常没有产品编号，不作为产品数据。
- 产品编号非空的行才进入产品预览。
- 产品编号去除首尾空格，并按不区分大小写的方式检测重复；数据库保存源表中的规范文本。
- 产品编号为空的行作为说明或空行忽略，不自动生成产品编号。

| 品牌 | 品牌 | 空字符串或 `NULL` |
| 系列 | 系列 | 空字符串或 `NULL` |
| 物料颜色 | 颜色 | 空字符串或 `NULL` |
| 锁体类型 | 锁体类型 | 空字符串或 `NULL` |
| 联网方式 | 联网方式 | 空字符串或 `NULL` |
| 销售渠道 | 销售渠道 | 空字符串或 `NULL` |
| 运营主体 | 运营主体 | 空字符串或 `NULL` |
| 语言 | 语言 | 空字符串或 `NULL` |
| 编码后缀 | 编码后缀 | 空字符串或 `NULL` |
| 型号（含换行标题） | 型号 | 空字符串或 `NULL` |
| 物料规格（含换行标题） | 物料规格 | 空字符串或 `NULL` |

## 供应商处理

- 供应商名称为空时，只导入产品，不创建供应商报价。
- 供应商名称非空时，按去空格、括号统一和不区分大小写的规则匹配已有供应商。
- 找不到供应商时，该行显示错误并禁止直接提交；用户应先在供应商管理创建或修正供应商名称。
- 匹配成功后创建产品与供应商关联，并写入含税采购价。
- 供应商最小起订量与销售最小起订量语义不同；本文件未提供供应商最小供应量时使用供应商报价记录的系统默认值 `1`，销售最小起订量仍保存到产品字段。

## 重复编号人工确认

冲突来源包括：

- 同一工作表内重复。
- 两个产品工作表之间重复。
- 预览数据与提交时数据库中已存在的产品编号冲突。

每个冲突组默认不选择处理方式，用户必须选择：

- `覆盖`：采用当前行，冲突组中其他同编号行跳过；如果是数据库已有记录，则以当前行字段完整覆盖。
- `跳过`：当前行不导入。

同一产品编号最多允许一行被选为覆盖。提交接口再次校验冲突选择，不能只依赖前端。

## 全量清理范围

全量替换仅用于开发环境。提交前显示不可逆警告，并在事务中按外键依赖顺序清理：

- 产品图片、产品供应商配置、库存余额、库存流水和成本历史。
- 销售订单明细及其关联的锁定、缺口、发货、收款、售后等业务数据。
- 采购建议明细、采购单明细、收货、付款及相关覆盖关系。
- 其他直接引用产品或上述业务单据的数据。
- 最后删除全部产品记录，再插入本次确认后的产品。

保留以下主数据和独立数据：

- 客户资料。
- 供应商资料。
- 用户和权限数据。
- 客户资金余额及不依赖被删订单的独立预付款记录；引用被删订单的关联标识需要解除或同步清理，确保外键一致。
- 产品编号规则配置。

## 安全与权限

- 全量替换仅管理员可以执行。
- 后端增加开发环境保护；生产环境默认拒绝全量清理，除非有明确的受控配置开关。
- 提交前要求二次确认，不允许点击遮罩触发提交或关闭确认。
- 预览与提交之间如果数据发生变化，提交阶段重新校验并返回冲突，不静默覆盖。
- 导入批次记录上传人、提交人、时间、来源文件名、成功数、跳过数和冲突选择。

## 错误处理

- 文件缺少任一指定产品工作表时，预览失败并指出缺失表名。
- 产品编号为空的说明行忽略；正式数据行的其他格式错误在预览中逐行显示。
- 供应商无法匹配、最小起订量不是正整数、价格不是非负数字时标记错误。
- 未处理的重复编号冲突禁止提交。
- 全量替换过程中任何SQL失败均回滚，并向用户显示可理解的错误，不留下半清理状态。

## 测试与验收

- 解析测试覆盖两个指定工作表、说明行跳过、空字段默认值和17条有效记录。
- 冲突测试覆盖表内重复、跨表重复、数据库重复以及覆盖/跳过选择。
- 供应商测试覆盖成功匹配、空供应商和未匹配错误。
- 事务测试验证清理与导入原子性，模拟写入失败后旧数据完整保留。
- 外键测试验证确认范围内的订单、库存、采购和产品关联数据均被正确清理，保留客户、供应商和用户。
- 前端测试验证冲突行必须手工处理、未确认不能提交、全量替换二次确认。
- 使用提供的 Excel 在本地开发数据库演练，最终应得到17个启用产品和正确的供应商报价关联。
