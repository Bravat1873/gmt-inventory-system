# 产品物料规格与字段语义调整设计

## 目标

统一产品字段含义，消除“系列/型号”“客户编号/客户料号”“物料规格/产品配置”的混淆，并确保物料规格由产品规则稳定生成。

## 页面与字段

- 产品编辑弹窗将“客户编号”改为“客户料号”，已有产品允许修改。
- “锁体颜色”改为“物料颜色”。
- “系列”选择继续保留，仅参与产品编号生成，不再作为产品管理列表展示列。
- 产品管理列表原“系列”列替换为“型号”，绑定 `model`。
- 现有 `configuration` 字段定义为“物料规格”，在编辑弹窗中只读显示，在列表中显示。
- 新增 `productConfiguration` 字段，标签为“产品配置”，可新增、修改并在产品管理列表中显示。

## 物料规格生成规则

物料规格按以下顺序使用可读名称，以 ` / ` 连接：

1. 品牌名称
2. 型号文本
3. 物料颜色名称
4. 锁体类型名称
5. 语言名称

示例：`STANLEY / D51-GEN2 / 宇宙黑 / 7068 / 中文版`。

空值不输出，也不产生多余分隔符。前端根据当前选择实时预览；后端在创建和修改产品时根据规则表重新计算并保存，后端结果为最终数据，避免绕过页面提交时产生不一致。

## 数据模型和兼容性

- 新增 `sku.product_configuration VARCHAR(500) NULL`。
- 继续使用 `sku.configuration` 保存物料规格，不迁移或覆盖已有记录；旧记录在下一次修改时按新规则生成。
- API 请求与响应新增 `productConfiguration`。
- 品牌规则迁移继续保留已有关联规则主键，并修正为 `SXSEL=STANLEY`、`BR=BRAVAT`、`G=GMT`。

## 验证

- 前端组件测试覆盖字段名称、列表字段、实时规格预览、客户料号可修改以及产品配置提交。
- 后端服务测试覆盖规格生成顺序、空值过滤和产品配置保存。
- 迁移测试覆盖 `product_configuration` 列和品牌规则。
- 使用本机 MySQL `localhost:3306/internal_ops` 执行 Flyway，不使用 Docker；启动前后端后通过页面检查编辑与列表显示。
