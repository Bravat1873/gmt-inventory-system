# 库龄与分批发货地址设计

## 目标

库存管理显示当前库存中最早一批货物的在库日期和库龄；订单每次实际发货都保存本批次独立的收货地址，支持同一订单不同批次发往不同地址。

## 库龄规则

- 库龄遵循先进先出（FIFO），以库存流水为事实来源。
- 按仓库和 SKU 将正数实际库存流水视为入库批次，负数实际库存流水依次消耗最早的未耗尽批次。
- 当前实际库存大于零时，最早仍有剩余数量的入库批次日期为“最早在库日期”。
- “库龄”是当前日期与最早在库日期之间的自然日天数，当天入库为 0 天。
- 当前实际库存为零、没有可识别入库流水或历史数据不足时，两个字段显示“—”，不猜测日期。
- 库存查询返回 `oldestStockDate` 和 `inventoryAgeDays`；列表新增“最早在库日期”和“库龄”两列。
- 新入库不会覆盖旧库存日期。只有更早批次被出库耗尽后，日期才移动到下一批。

## 发货批次与地址

- 新建 `sales_shipment` 表保存发货批次头：订单、批次号、收货地址、发货时间、操作人和备注。
- 新建 `sales_shipment_item` 表保存本批次各订单行的增量发货数量。
- 发货弹窗增加“本批收货地址”，默认值优先取订单快照中的收货地址；为空时取客户当前地址。
- 地址允许在本次发货前修改，保存后作为该批次快照，不随客户资料后续修改。
- 一次保存中所有正向发货增量属于同一批次，并共用一个收货地址；没有正向增量时不创建发货批次。
- 有正向增量时地址必填，后端同时校验，避免绕过页面产生空地址批次。
- 调低累计发货数量仍沿用现有库存回退逻辑，但只记录调整流水，不创建虚假的正向发货批次。
- 订单详情返回默认发货地址及历史批次，便于后续追溯每批时间、地址和数量。

## 数据流

1. 打开发货弹窗时，订单详情携带默认地址和历史发货批次。
2. 用户调整各行累计发货数量并确认本批地址。
3. 后端锁定订单与明细，计算相对当前累计值的增量。
4. 正向增量通过现有库存校验后扣减库存，并在同一事务内写入发货批次及批次明细。
5. 库存列表查询根据实际库存流水执行 FIFO 余额计算，返回最早在库日期和库龄。

## 兼容与错误处理

- 数据库迁移只新增表和索引，不破坏现有订单及库存数据。
- 历史发货因没有地址批次记录，不反向虚构地址；仅新功能启用后的正向发货形成批次。
- 发货保存中的订单状态、数量上限、备货量和库存校验保持不变。
- 任一库存扣减或批次写入失败时整笔事务回滚。
- 地址去除首尾空格后保存，并限制在数据库字段允许长度内；超长或空白地址返回明确错误。

## 界面

- 库存列表将“最早在库日期”“库龄”放在库存数量区域之后，库龄显示为“123 天”。
- 发货弹窗在汇总信息和明细表之间增加醒目的地址输入区，文案说明该地址只用于本批发货。
- 弹窗可展示历史发货批次的日期、地址和数量摘要，帮助确认不同批次的去向。

## 测试

- 后端测试覆盖：多批入库 FIFO、部分出库、跨批次出库、零库存、流水不足。
- 发货接口测试覆盖：默认地址、修改地址、正向增量生成批次、多行合并为同一批、空地址拒绝、减少数量不生成正向批次、事务回滚。
- 前端测试覆盖：库龄列映射、默认地址显示、地址可编辑、请求载荷包含地址、未填写地址时阻止保存、历史批次展示。
