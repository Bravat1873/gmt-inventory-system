# 供应商产品多版采购信息设计

## 目标

同一个供应商与产品关系可以维护多条采购信息。每条采购信息包含采购单价、最小起订量、交货天数和系统维护的修改时间。采购管理只从这些供应商采购信息中选择价格，不再使用产品的成本单价或转厂价格。

同时修复供应商修改页中产品名称被截断后无法查看全名的问题：列表保持单行固定高度，鼠标悬浮时显示完整产品名称。

## 核心业务规则

1. 一个产品可以关联多个供应商。
2. 同一个“供应商＋产品”可以有多条采购信息。
3. 每条采购信息是独立记录，包含：
   - 采购单价；
   - 最小起订量；
   - 交货天数；
   - 修改时间；
   - 是否有效。
4. 修改已有采购信息会更新该记录及其修改时间；新增采购信息会创建新记录。
5. 手工采购选择产品后，只显示能供应该产品且存在有效采购信息的供应商。
6. 选择供应商后，采购单价下拉列出该供应商对该产品的全部有效采购信息，并默认选中修改时间最新的一条。
7. 切换采购信息时，同步更新采购单价、最小起订量、交货天数以及根据交货天数计算的预计到货日期。
8. 采购数量不得低于所选采购信息的最小起订量。
9. 创建采购单时保存所选采购信息记录 ID 和当时的采购单价快照。以后采购信息发生变化，不修改历史采购单。
10. 自动生成采购建议时，对每个供应商和产品使用修改时间最新的有效采购信息。
11. 采购管理中彻底移除“成本单价（含税）”“转厂价格”“价格来源”“CURRENT_COST”“FACTORY_PRICE”等采购价格来源概念。

## 数据模型

保留 `sku_supplier_config` 作为供应商与产品的唯一供应关系，继续使用 `(sku_id, supplier_id)` 唯一约束。

新增 `sku_supplier_purchase_info` 表：

- `id`：采购信息 ID；
- `supplier_product_config_id`：关联 `sku_supplier_config.id`；
- `purchase_price DECIMAL(18,4)`；
- `moq INT`；
- `lead_time_days INT`；
- `enabled BOOLEAN`；
- `created_at DATETIME`；
- `updated_at DATETIME`；
- `version INT`。

现有 `sku_supplier_config` 中的采购单价、最小起订量和交货天数迁移为每个供应关系的第一条采购信息，确保已有数据不丢失。旧列暂时保留以降低迁移风险，但新业务读写不再使用它们；后续可在独立迁移中删除。

在 `purchase_order_item` 增加可空的 `supplier_purchase_info_id`。旧采购单保持为空，新采购单保存所选记录 ID，同时继续保存 `purchase_price` 快照。

## 供应商管理页面

供应产品区域按产品分组，一个产品只显示一次。

- 产品名称保持单行省略，不撑高表格；使用现有溢出文本交互或原生标题提示，悬浮显示完整名称。
- 每个产品下方显示可变采购信息列表。
- 每条显示采购单价、最小起订量、交货天数、修改时间和删除操作。
- 可在当前产品组内点击“新增采购信息”。
- 新增但尚未保存的记录，修改时间显示“保存后生成”。
- 已保存记录的修改时间只读。
- 删除操作在保存供应商时将对应采购信息设为无效，不物理删除历史记录。
- 删除产品关系时，将该供应关系及其全部采购信息设为无效；历史采购单仍可通过已保存的记录 ID 和价格快照追溯。

## 手工采购页面

交互顺序保持“产品 → 供应商 → 采购信息”：

1. 选择产品；
2. 查询并选择可供应该产品的供应商；
3. 加载该供应商与产品的有效采购信息；
4. 默认选择 `updated_at DESC, id DESC` 的第一条；
5. 采购信息下拉项显示：`¥单价｜起订 N｜交货 N 天｜YYYY-MM-DD HH:mm`；
6. 页面显示当前采购信息的最小起订量和交货天数；
7. 根据交货天数自动填充预计到货日期，用户仍可手工调整；
8. 保存时提交 `supplierPurchaseInfoId`，不再提交 `priceSource`。

后端根据采购信息 ID重新查询供应商、产品、价格、起订量和交货天数，校验其与当前选择一致。前端提交的采购单价只作显示或兼容，不作为可信来源。

## 自动采购建议

自动生成建议时，每个供应商产品关系只连接其最新有效采购信息。若同一产品存在多个供应商，自动建议选择采购信息修改时间最新的供应商；时间相同时按采购信息 ID 较大的记录确定，避免同一缺口被多家供应商重复覆盖。最终使用该记录计算建议数量、采购单价和预计到货日期。

如果某供应关系没有有效采购信息，视为不可用于采购，并给出明确提示，避免产生空价格采购建议。

## 接口调整

供应商详情与保存接口中的产品结构调整为：

```text
product {
  skuId,
  purchaseInfos: [{ id?, purchasePrice, moq, leadTimeDays, updatedAt?, version? }]
}
```

产品供应商选项接口返回供应商基本信息，并附带其最新采购信息和采购信息数量。新增采购信息列表接口按修改时间倒序返回指定供应商产品关系的有效记录。

手工采购请求调整为：

```text
{
  supplierId,
  skuId,
  supplierPurchaseInfoId,
  quantity,
  expectedArrivalDate,
  remark
}
```

移除 `priceSource`，后端不再读取 SKU 的 `current_cost` 或 `factory_price` 作为采购价格。

## 校验与错误处理

- 采购单价必须是最多四位小数的非负数；
- 最小起订量必须大于零；
- 交货天数不能为负数；
- 每个供应产品至少保留一条有效采购信息；
- 采购信息必须属于提交的供应商与产品；
- 已停用或不存在的采购信息不能下单；
- 采购数量低于所选最小起订量时拒绝保存；
- 并发修改使用 `version` 校验，提示用户重新打开页面。

## 测试与验收

后端测试覆盖数据迁移、多条采购信息保存、修改时间排序、最新记录选择、手工采购归属校验、最小起订量校验、价格快照和自动建议最新信息选择。

前端测试覆盖产品全名悬浮、多条采购信息增删编辑、修改时间显示、采购信息下拉、默认最新记录、切换记录后的起订量和预计到货联动，以及成本价和转厂价选项完全消失。

浏览器验收重点检查供应商修改弹窗不被多条信息异常撑宽、产品名称悬浮可读、手工采购默认最新价格，并确认历史采购单价格不会随采购信息修改而改变。
