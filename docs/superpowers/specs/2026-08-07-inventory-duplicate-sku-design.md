# 库存导入重复 SKU 合并设计

## 背景

库存工作簿中可能多次出现同一个物料编号。当前校验逻辑会把这些行全部标记为错误，导致对应 SKU 既不能写入库存，也不能自动创建到产品资料。

样例文件中的 `SXSEL_P90YZH70WPSE-A` 出现两次；用户提到的 `SXSEL_P90YZH70WPSE-z` 并不存在于该文件。

## 已确认规则

- 同一个库存文件内，SKU 去除首尾空格后按不区分大小写判定重复。
- 第一次出现的 SKU 行是主记录，保留其产品资料以及全部库存数量。
- 后续相同 SKU 行不参与提交、不累加数量、不覆盖第一行。
- 主记录正常经过字段校验和数据库冲突检查。
- 后续重复行在预览中标记为 `IGNORED`，提示采用第一条记录及其 Excel 行号，而不是标记为错误。
- SKU 原始大小写以第一条记录为准，系统只去除首尾空格。
- 有效库存主记录提交时继续复用现有 `upsertSku`：新 SKU 自动创建产品，已有 SKU 更新产品；随后写入对应库存。

## 数据流

1. Excel 解析器按工作表和行号产生库存记录。
2. 校验服务按原始顺序维护首个 SKU 的行号。
3. 首次出现的 SKU 执行正常库存校验。
4. 后续重复 SKU 转为 `IGNORED`，保留原始数据用于预览追溯。
5. 提交服务只提交 `VALID` 主记录，因此产品和库存都只采用第一行。

## 异常与边界

- 空 SKU 仍按原规则报错，不能参与去重。
- 如果第一行本身数量非法，第一行仍报错；后续重复行不会顶替第一行。
- `sku-a` 与 `SKU-A` 被视为同一个 SKU，最终保留第一行的写法。
- 数据库已有相同 SKU 时，第一行仍按现有冲突策略处理。

## 验证

- 单元测试证明重复 SKU 的第一行有效、第二行忽略，且提示包含第一行行号。
- 单元测试证明第一行库存非法时不会由第二行替代。
- 提交集成测试证明新库存 SKU 会自动创建一个产品，并使用第一行库存数量。
- 运行导入模块测试及完整后端测试，确认既有客户、成本和库存导入不受影响。
