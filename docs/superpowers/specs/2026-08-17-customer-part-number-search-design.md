# 客户料号统一与产品搜索设计

## 目标

整个系统彻底移除“物料编号”概念，将对应数据库列、后端字段、接口字段、导入表头和前端文案统一为“客户料号”。产品搜索只允许通过客户料号、型号和产品编号进行。

## 数据模型

- 将 `sku.sku_code` 无损重命名为 `sku.customer_part_number`，保留现有数据值和空值约束。
- 将售后历史快照等业务表中的 `sku_code` 列同步重命名为 `customer_part_number`。
- 相关索引名称改为客户料号语义。
- 使用新的 Flyway 迁移执行列重命名，不修改已经执行过的历史迁移。
- 不提供旧列、数据库视图或兼容别名。

## 后端与接口

- Java 字段、DTO、记录类型和 JSON 字段统一为 `customerPartNumber`。
- SQL 全部读取 `customer_part_number`，删除产品领域中的 `skuCode` 输出。
- 产品列表和所有产品选择接口的关键字查询仅匹配：`customer_part_number`、`model`、`product_code`。
- Excel 解析器和模板只接受“客户料号”表头，不再接受“物料编号”旧表头。

## 前端交互

- 全系统所有可见“物料编号”文案改为“客户料号”。
- 所有产品搜索框提示统一为“输入客户料号、型号或产品编号搜索”。
- 产品候选项及供应商产品行只显示客户料号、型号和产品编号。
- 三项信息全部显示并允许换行，不使用省略号、折叠或仅悬停查看。
- 供应商产品表保持稳定最小宽度，容器始终支持底部水平滚动；操作列内容不得被裁切。

## 测试与发布

- 先添加失败测试，覆盖数据库新列、限定搜索字段、前端三字段展示、完整文本和水平滚动。
- 运行相关后端测试、前端测试和构建。
- 执行数据库迁移，重建并重启项目。
- 在浏览器中验证供应商弹窗的搜索、完整展示和水平滚动。

## 非目标

- 不保留旧 Excel 表头兼容。
- 不保留旧 `skuCode` API 字段兼容。
- 不改变客户料号现有数据值。
