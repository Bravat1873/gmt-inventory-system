# 管理页面排序与弹窗关闭统一设计

## 目标

为所有管理列表的适合字段提供稳定、安全、符合业务流程的排序；统一所有弹窗的关闭行为，并修复主操作按钮禁用时“关闭/取消”也无法使用的问题。

## 列表排序设计

列表继续采用点击表头排序。第一次点击按升序，再次点击按降序；切换字段时新字段从升序开始。排序参数继续写入 URL，翻页和刷新后保持当前排序。

前端的表头可排序配置与后端排序白名单必须一一对应。后端仅接受白名单字段，并始终追加稳定的记录 ID 次级排序，防止相同值在分页间跳动。

### 可排序范围

- 客户管理：客户编号、客户名称、订单联系人、订单联系电话、合同状态、合同截止日期、修改时间。
- 用户管理：用户名、姓名、角色、修改时间。
- 产品管理：产品编号、客户料号、品牌、型号、产品分类、物料类型、销售最小起订量、修改时间。
- 供应商管理：制造商类别、制造商类型、供应商所在地、产品属性、简称、供应商名称、联系人、职务、电话、币种、税务登记号、开户银行、银行账号、供应产品数、修改时间。
- 订单管理：订单编号、客户、订单金额、订单状态、订单日期、销售人员、创建时间、修改时间。
- 售后管理：售后单号、原订单号、客户、售后类型、退货数量、换货数量、状态、申请日期、修改时间。
- 库存管理：产品编号、型号、产品分类、单位、实际库存、未锁定库存、最早入库日期、库龄、锁定数量、在途数量、未发货数、供需余量、来源供应商、修改时间。
- 采购管理：采购单号、供应商、订单金额、付款状态、收货状态、采购状态、预计到货日期、修改时间。
- 财务管理：业务编号、业务类型、往来单位、应收/应付、已收/已付、未收/未付、状态、修改时间。

以下字段不排序：图片、备注、地址、产品配置、物料规格、供应商报价、产品汇总等长文本或组合展示字段，以及操作列。

### 状态业务顺序

- 订单：草稿 → 待客户付款/确认 → 等待齐货 → 等待发货 → 已发货。
- 售后：待收退货 → 已收退货/待发换货 → 已完成 → 已取消；不同售后类型共享同一进度层级。
- 采购：草稿/采购建议 → 待付款 → 采购执行中 → 已入库/已完成。
- 采购付款：未付款 → 部分付款 → 已付款。
- 采购收货：未收货 → 部分收货 → 已收货。
- 财务：待收款/待付款 → 部分结算（若存在）→ 已收清/已付清。
- 客户合同：未设置合同 → 有效 → 已到期。
- 用户角色：管理员 → 财务 → 普通用户。
- 产品和供应商的分类枚举按页面业务选项顺序排序。

升序按以上流程从前到后，降序反向。未知历史状态统一排在已知状态之后。

## 弹窗关闭设计

所有业务弹窗使用一致规则：

- 右上角“关闭”、底部“取消操作”和键盘 `Esc` 都发起关闭。
- 点击弹窗外的灰色遮罩不关闭。
- 没有发生用户修改时直接关闭。
- 用户修改过表单时，关闭前提示“当前修改尚未保存，确定放弃吗？”。确认后关闭，取消则保留弹窗和内容。
- 只读弹窗直接关闭。
- 仅在实际保存请求进行期间禁止关闭，防止请求完成后状态不一致。
- 主操作按钮因业务条件禁用（例如未收金额为零）不得影响关闭按钮。

根因修复放在统一关闭守卫中：删除“弹窗中存在禁用主按钮就拦截关闭”的判断，以明确的保存中状态作为唯一禁止关闭条件。各弹窗保留自身 `saving` 状态，并统一接入关闭请求。

## 测试与验收

- 配置测试验证每个模块所有预期短字段都有排序键，排除字段没有排序键。
- 后端测试验证所有公开排序键可用、非法键回退安全默认排序、相同值使用稳定次级排序。
- 状态排序测试使用乱序数据，分别验证升序和降序符合业务流程。
- 弹窗回归测试复现“主按钮禁用但关闭按钮应可用”。
- 统一行为测试验证右上关闭、取消、`Esc`、修改确认、保存中禁止关闭，以及点击遮罩不关闭。
- 完整运行前后端测试和前端生产构建，并在本地浏览器检查代表性页面后部署服务器。

## 非目标

- 不增加拖拽排序、自定义排序规则或多列组合排序界面。
- 不允许点击遮罩关闭弹窗。
- 不对图片、长描述、备注或组合列表内容提供排序。
