# 库存产品类型双向编辑与售后订单选择修复设计

## 目标

- 产品管理和库存管理都可以修改同一 SKU 的产品类型，采用最后一次保存生效。
- 售后新增页面能够加载有已发货明细的原销售订单，并按订单修改时间倒排。

## 数据设计

产品类型仍只存储在 `sku.product_type`，不在库存表中复制字段。库存编辑提交 `productType` 后，后端在同一事务内更新对应 SKU；产品管理编辑继续更新同一字段，因此两端天然保持一致。

售后订单下拉查询去掉会触发 MySQL 8 错误的 `DISTINCT + ORDER BY 未选择字段` 组合，改为按订单聚合：`GROUP BY o.id, o.order_no, c.customer_name, o.updated_at`，并继续要求至少一条 `shipped_quantity > 0` 的明细。

## 界面行为

- 库存“产品类型”使用与产品管理相同的 `PRODUCT_TYPE` 选项，不再只读。
- 选择产品时自动带出当前类型；库存保存成功后，列表重新查询并显示最新类型。
- 售后下拉只列出存在已发货数量的订单；选中后加载可退明细。

## 验证

- 前端测试验证库存产品类型可编辑并随产品选择带入。
- 后端测试验证库存保存同步更新 SKU 产品类型。
- 后端测试验证 MySQL 兼容的售后订单查询结构及返回顺序。
- 本机 MySQL 启动最新版后端，实际登录调用售后订单接口并确认返回订单。
