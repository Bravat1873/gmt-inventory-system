# 产品导入自动生成产品编号与物料规格设计

## 背景

产品 Excel 的两个受支持工作表为“GMT库存产品清单”和“贝朗库存产品清单”。表内包含“产品编号（不用写）”和“物料规格（不用写，会自动生成）”两列。当前产品编号已通过系统编码规则生成，但产品全量替换仍会把 Excel 的物料规格写入 `sku.configuration`，与手工新增、编辑产品时的自动生成行为不一致。

## 目标

- 产品编号只由系统产品编码规则生成，Excel 原值不参与预览、校验或保存。
- 物料规格只由系统规格规则生成，Excel 原值不参与预览、校验或保存。
- 手工新增、编辑和 Excel 产品导入共用同一套物料规格生成实现。
- 修正当前 17 条已导入产品的物料规格，同时保持库存、库存供应商及产品供应商关联不变。

## 生成规则

### 产品编号

继续使用现有 `ProductCodeGenerator`：按品牌、系列、物料颜色、锁体类型、联网方式、销售渠道、运营主体、语言八项规则生成基础编号，并追加可选编码后缀。Excel 的“产品编号”列仅作为源文件兼容字段，不作为业务输入。

### 物料规格

统一按以下顺序拼接非空展示值，分隔符为 ` / `：

1. 品牌规则展示名
2. 型号
3. 物料颜色规则展示名
4. 锁体类型规则展示名
5. 语言规则展示名

示例：`GMT / T5-Max / 宇宙黑 / 6068 / 中文版`。

## 架构

新增一个无状态的共享物料规格生成组件。组件接收品牌规则 ID、型号、颜色规则 ID、锁体规则 ID、语言规则 ID，通过产品编码规则表读取展示名并生成规格。

`MasterDataCommandService` 的产品新增与编辑改为调用共享组件；`ProductReplaceImportService` 在写入 `sku.configuration` 时也调用同一组件。这样规则只有一个实现位置，后续规则调整不会在手工维护与 Excel 导入之间产生差异。

`ProductWorkbookExcelParser` 不再把 Excel 的产品编号和物料规格作为可提交业务字段。为了兼容现有模板，列可以继续存在，但内容被忽略。

## 数据流

1. 解析两个指定产品工作表。
2. 读取编码选择项、型号、产品配置、客户料号、供应商、价格、库存等允许导入的字段。
3. 产品编码解析器依据规则生成产品编号和规则指纹。
4. 提交时重新校验规则指纹。
5. 共享规格生成器依据规则展示名和型号生成物料规格。
6. 写入产品、供应商关系；库存和供应商字段沿用当前已确认的数据。

## 错误处理

- 规格所需的规则 ID 不存在或类别不匹配时，整次产品全量替换回滚。
- 编码规则在预览和提交之间发生变化时，继续拒绝提交并要求重新预览。
- Excel 中产品编号或物料规格无论为空、错误或含公式，都不会影响导入结果。

## 数据修正

部署新实现后，依据当前 17 条产品已保存的规则 ID 和型号重新计算 `sku.configuration`。不重新创建产品，不更改产品 ID，不删除库存，不改变库存数量、库存供应商、产品供应商配置或采购价格。

## 测试

- 解析器测试：Excel 中填写任意产品编号和物料规格，解析结果不包含可提交的源字段。
- 产品替换测试：Excel 提供错误物料规格时，数据库仍保存系统生成值。
- 共享规则测试：手工产品与导入产品对相同规则选择生成完全一致的规格。
- 回归测试：产品编号仍由八项编码规则及后缀生成。
- 数据验证：17 条产品规格均符合五段规则；产品数、库存数、库存合计和供应商关联在修正前后保持一致。

## 非目标

- 不修改 Excel 文件本身。
- 不改变产品编码规则配置、物料规格字段格式或库存计算规则。
- 不导入第三个“库存数量”工作表。
