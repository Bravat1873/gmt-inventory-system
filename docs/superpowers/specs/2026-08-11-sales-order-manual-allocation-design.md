# 销售订单手动库存分配设计

## 目标

销售订单确认后自动尽量锁定库存，同时允许在未发货前手动调整每条订单明细分配给客户的锁定数量，并允许安全修改订单产品和数量。

## 业务规则

- 订单保存为“确认订单并分配库存”时，系统按现有规则自动尽量锁满订单数量。
- 订单列表新增“库存分配”操作，逐行展示订单数量、已发货数量、当前锁定、未覆盖、实际库存和可增配数量。
- 人工分配目标必须在 `0` 到 `订单数量 - 已发货数量` 之间。
- 增配不得超过库存余额中未被其他订单锁定的数量；减配立即释放库存。
- 每次增配或释放均写入 `inventory_transaction`，分别使用 `MANUAL_ALLOCATE` 和 `MANUAL_RELEASE` 类型。
- 调整后：所有未发货数量均被锁定时，订单状态为 `READY_TO_SHIP`；否则为 `WAITING_STOCK`。
- 已发生任何发货后，禁止修改产品、订单数量或手工锁定数量；仍可使用现有发货流程。
- 尚未发货的 `READY_TO_SHIP`、`WAITING_STOCK`、`PENDING_CUSTOMER_PAYMENT` 和 `DRAFT` 订单允许修改。

## 订单修改

修改订单时在同一事务内锁定订单、明细和库存余额。对原明细的所有锁定先写释放流水并归还库存，再更新订单和明细，最后在目标状态为非草稿时按新明细重新自动分配。这样产品替换、删除明细、减少数量和增加数量都不会遗留旧锁定。若事务中任一步失败，订单、明细、库存余额和流水全部回滚。

草稿订单不锁库存。把已确认但未发货订单改回草稿时释放全部锁定。已有发货的订单拒绝上述修改，不尝试重写历史出库记录。

## 后端接口

- `GET /api/orders/{id}/allocations`：返回订单版本、状态、是否可调整及逐行库存分配数据。
- `PUT /api/orders/{id}/allocations`：请求包含订单 `version` 和每条明细的 `lineNo`、目标 `lockedQuantity`。
- 服务端校验明细集合、数量范围、库存可用量和版本；使用数据库行锁与事务保证一致性。

## 前端

订单列表对未发货订单提供“库存分配”按钮。弹窗逐行显示产品、订单数、当前锁定、未覆盖、实际库存、可用库存及“分配数量”数字输入框。默认填入当前锁定数量。保存后刷新订单列表并显示成功或明确错误信息。

订单编辑弹窗允许打开未发货的待发货/等待库存订单；已有发货时后端返回明确阻止原因。

## 测试

- 自动分配后手动减配会释放库存并写流水。
- 手动增配在可用范围内成功，超出可用库存失败且不产生部分更新。
- 状态在 `READY_TO_SHIP` 与 `WAITING_STOCK` 间正确切换。
- 修改订单会释放旧锁定、保存新明细并重新分配。
- 改回草稿释放全部锁定。
- 已发货订单、过期版本、重复/缺失行号均被拒绝。
