# 产品图片图库设计

## 目标

在产品管理中为每个产品维护一张主图和多张详情图。产品列表使用紧凑缩略图展示主图，点击后打开完整图库。图片先保存在服务器本地 Docker 持久化卷中，并通过独立存储接口隔离业务逻辑，为未来切换 MinIO 或其他 S3 对象存储保留空间。

## 范围

- 每个产品最多保存 10 张图片，其中一张为主图。
- 单张图片最大 5MB。
- 支持 JPEG、PNG 和 WebP。
- 所有已登录用户均可查看、上传、删除、排序和设置主图。
- 新增产品时可同时选择图片，产品资料保存成功后自动上传图片。
- 产品列表展示主图缩略图和图片总数，点击缩略图打开图库。
- 本期不接入 MinIO，不处理视频、文档、图片编辑和自动抠图。

## 页面与交互

### 产品列表

产品表格最左侧增加“图片”列：

- 显示约 56×56 像素的主图缩略图。
- 多图时在缩略图右下角显示图片总数。
- 无图片时显示统一的“暂无图片”占位。
- 点击缩略图或占位区域打开该产品的图库。
- 保持现有表格布局和分页方式，不改为卡片列表。

### 新增和修改产品

产品弹窗增加独立的“产品图片”区域：

- 支持点击选择和拖拽添加图片。
- 选择后立即在本地显示预览，但新增产品尚未保存时不上传服务器。
- 第一张图片默认成为主图。
- 可设置任意图片为主图、拖动调整顺序或删除待上传图片。
- 清楚展示数量、单张大小和格式限制。
- 修改产品时展示已有图片，并允许与新图片一起排序。

新增产品的保存顺序为：先保存产品资料，获得产品 ID 后按界面顺序上传图片。图片上传失败不回滚已经创建的产品，页面保留失败项并提示具体原因，用户可直接重试。

### 图库

- 弹窗中显示大图和缩略图列表。
- 支持上一张、下一张、点击缩略图切换和关闭。
- 明确标记主图。
- 维护入口沿用新增/修改产品弹窗，图库以查看为主，避免一个弹窗承载过多操作。

## 数据模型

新增 `product_image` 表，建议字段：

- `id`：主键。
- `product_id`：关联产品 ID，建立索引和外键约束。
- `storage_key`：相对于图片根目录的不可猜测对象键。
- `original_filename`：原始文件名，仅用于展示。
- `content_type`：经服务端检测后的媒体类型。
- `file_size`：文件字节数。
- `is_primary`：是否主图。
- `sort_order`：从 0 开始的显示顺序。
- `uploaded_by`：上传用户 ID 或用户名。
- `created_at`、`updated_at`：审计时间。
- `version`：用于并发更新控制。

约束规则：

- 一个产品最多 10 条有效图片记录。
- 一个有图片的产品必须且只能有一张主图。
- `storage_key` 全局唯一。
- 删除主图后，剩余图片中 `sort_order` 最小的一张自动成为主图。
- 重新排序后将顺序规范化为连续值。

产品列表接口返回主图的受保护访问地址或图片 ID，以及图片总数；不在列表响应中返回所有图片详情。图库通过独立接口按产品加载完整图片元数据。

## 本地存储

图片根目录由配置项控制，例如 `PRODUCT_IMAGE_ROOT=/data/product-images`。Docker Compose 为该目录挂载独立命名卷：

- 重新构建或普通 `docker compose down` 不删除图片。
- `docker compose down -v` 会删除图片卷，行为与用户当前允许清空服务器数据的部署方式一致。
- 数据库与图片卷必须成对备份，否则可能产生缺失文件或孤立文件。

文件使用随机 UUID 对象键，不直接使用用户提供的文件名，目录可按产品 ID 分层。下载和预览统一通过后端鉴权接口，不直接暴露宿主机路径。

存储实现通过 `ProductImageStorage` 接口封装上传、读取和删除操作。本地文件系统是首个实现；未来接入 MinIO 时新增 S3 实现，不改变产品图片业务接口和数据库结构。

## API 与数据流

建议提供以下后端能力：

- 查询产品图片列表。
- 批量上传一个或多个产品图片。
- 获取图片内容或缩略图。
- 设置主图。
- 提交完整排序。
- 删除单张图片。

所有接口必须要求登录。上传操作在服务端再次校验产品存在、当前图片数量、单文件大小、文件签名和实际媒体类型。数据库记录只在文件成功写入后创建；若数据库写入失败，则删除刚写入的文件进行补偿。

删除图片时先标记或删除数据库记录，再删除文件。文件删除失败需要记录日志并允许后台清理，不能让接口返回成功却无任何审计线索。删除产品时级联删除图片记录，并由业务服务清理对应文件。

## 图片安全与性能

- 不信任扩展名或浏览器传入的 `Content-Type`，服务端检测文件签名。
- 拒绝 SVG、HTML、脚本和非图片内容。
- 响应设置正确的 `Content-Type`、缓存头和 `X-Content-Type-Options: nosniff`。
- 原图限制 5MB；列表优先使用缩略图，避免直接加载大图。
- 缩略图可在上传时生成并保存；生成失败时保留原图但记录错误，列表使用占位图，允许重试。
- 文件名、路径和错误信息不得泄露服务器真实目录。

## 错误处理

- 格式错误、超过 5MB、超过 10 张分别给出明确中文提示。
- 批量上传返回逐文件结果，部分失败不影响已成功图片。
- 新增产品成功但图片失败时，提示“产品已保存，部分图片上传失败”，保留失败项供重试。
- 设置主图、排序和删除采用版本或事务控制，避免多人同时维护造成多主图或顺序冲突。
- 数据库中存在记录但文件缺失时，图片接口返回占位状态并记录错误，而不是返回服务器异常页面。

## 测试与验收

后端测试覆盖：

- JPEG、PNG、WebP 正常上传。
- 伪造扩展名、非法内容、超大文件和第 11 张图片被拒绝。
- 首图自动成为主图，设置主图后唯一性保持正确。
- 删除主图后自动选择下一张。
- 排序、并发版本冲突和产品删除清理。
- 未登录访问被拒绝，三种已登录角色均可维护。
- 文件写入成功但数据库失败时执行补偿删除。

前端测试覆盖：

- 列表缩略图、数量角标和无图占位。
- 点击打开图库及图片切换。
- 新增产品先保存资料再上传图片。
- 拖拽排序、设置主图、删除和失败重试。
- 数量、格式及大小的即时提示。

部署验收覆盖：

- Docker Compose 创建并挂载图片命名卷。
- 重建前后端容器后图片仍可访问。
- 清除命名卷后系统能以无图片状态正常启动。

## 已确认决策

- 使用表格缩略图布局，不改成产品卡片页。
- 使用本地 Docker 持久化卷，本期不使用 MinIO。
- 一张主图加多张详情图，最多共 10 张。
- 单张最大 5MB，支持 JPEG、PNG、WebP。
- 所有已登录用户都可以维护产品图片。
- 新增产品时可以同时选择图片并一次完成保存流程。
