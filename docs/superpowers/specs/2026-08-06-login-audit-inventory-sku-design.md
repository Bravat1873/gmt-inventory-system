# 登录、操作审计与库存 SKU 匹配设计

## 目标

为内部管理系统增加受保护的用户名密码登录、可追溯的后台操作日志，以及产品 Excel 导入时从已导入库存数据自动匹配 SKU 的能力。

## 已确认的规则

- 首个管理员为 `admin`，初始密码为 `123`。
- 使用服务端会话：浏览器只保存 HttpOnly Cookie，不保存密码或可读令牌。
- 所有业务接口均需登录；登录、退出和健康检查除外。
- 所有会改变业务数据的操作均记录操作人、服务器时间、动作、业务对象和变更摘要。
- 产品导入优先使用 Excel 自带 SKU；SKU 为空时，按型号、颜色、锁体在已导入库存对应的产品中唯一匹配。
- 找不到唯一库存 SKU 时，预览保留空 SKU，标记为“未匹配，请填写”；不自动生成 SKU，也不允许该行确认导入。
- 已存在的 SKU 仍按现有“跳过/覆盖”冲突选择执行。

## 架构

后端新增认证模块，使用 `sys_user` 存储 BCrypt 密码哈希，使用独立会话表存储已哈希的随机会话令牌及过期时间。认证过滤器从 HttpOnly Cookie 解析当前用户并把用户身份绑定到请求上下文。所有写服务通过统一审计服务写入现有 `operation_log` 表，时间由服务器生成。

前端启动时获取当前会话；未登录时只显示登录页。登录成功后显示现有工作台，右上角显示当前用户名与退出入口。所有 API 请求携带 Cookie。

## 接口

- `POST /api/auth/login`：接收用户名和密码，成功后写入会话 Cookie，返回当前用户。
- `POST /api/auth/logout`：失效当前会话并清除 Cookie。
- `GET /api/auth/me`：返回当前登录用户。
- `GET /api/operation-logs`：管理员查看操作时间、操作人、动作和对象的分页日志。

## 数据与审计

- 新增 `user_session`：用户 ID、令牌哈希、创建时间、过期时间、注销时间。
- 数据迁移确保 `admin` 用户存在；仅保存 BCrypt 哈希，绝不保存明文 `123`。
- 导入确认记录批次号、导入类型、新增/更新/跳过数量和当前用户。
- 产品、客户、库存、订单、采购、付款、用户新增及修改都写操作日志；读取、筛选和预览不写日志。

## 产品导入 SKU 匹配

1. Excel 行含 SKU 时，以该 SKU 为准。
2. SKU 为空时，查询 `inventory_balance` 关联的 `sku`，以标准化后的“型号 + 颜色 + 锁体”查找。
3. 仅找到一条时回填该 SKU，按现有冲突策略处理。
4. 找不到或找到多条时，行状态为异常，SKU 输入框保持可编辑，并显示匹配原因。
5. 用户填写 SKU 并保存后重新校验；没有有效 SKU 的产品行不可提交。

## 验证

- 后端覆盖：登录成功/失败、未登录拒绝、退出失效、审计操作人及时间、库存唯一匹配、无匹配和多匹配阻止产品导入。
- 前端覆盖：登录页、会话恢复、退出、未匹配 SKU 提示。
- 使用现有三份 Excel 预览验证：产品表 SKU 能从库存数据回填；库存重复 SKU 继续以异常提示，绝不合并。
