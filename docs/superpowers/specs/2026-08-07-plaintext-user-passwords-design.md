# 用户明文密码管理设计

## 目标

管理员新增账号时直接设置初始密码，并可在修改账号时重置密码。系统不要求首次登录修改密码，不设置长度、字符种类或复杂度规则，`123` 等简单密码可以使用。

按照已确认的业务决定，所有账号密码均以明文形式保存，不再使用 BCrypt 或其他不可逆加密。

## 权限范围

- 只有 `ADMIN` 可以新增用户、修改用户资料、分配角色和重置密码。
- `FINANCE` 与 `USER` 可以查看用户列表，但不能打开新增或修改用户表单，也不能通过接口执行用户写入。
- 后端对用户新增和修改接口强制校验管理员角色，前端隐藏或禁用对应操作只是交互辅助。

## 新增账号

用户表单增加“初始密码”字段：

- 新增账号时必填。
- 只校验非空，不限制长度或复杂度。
- 输入框使用密码类型，页面不回显输入内容。
- 后端去除首尾空白后，直接将密码写入 `sys_user.password_hash` 现有字段。为避免高风险数据库结构变更，本次保留历史列名，但该列内容改为明文密码。
- 用户查询和命令响应绝不返回密码字段。

## 修改与重置密码

修改账号时显示“重置密码”输入框：

- 留空或不提交：保留数据库中的原密码。
- 填写任意非空内容：直接以明文替换原密码。
- 不提供查看、复制或恢复旧密码的接口。
- 用户角色、启用状态和资料继续按现有乐观锁规则更新。

## 现有账号迁移

新增 Flyway 数据库迁移，将所有现有 `sys_user.password_hash` 统一更新为明文 `123`。

迁移后：

- 管理员和所有已有账号均使用密码 `123` 登录。
- 原 BCrypt 密码立即失效，不再保留兼容登录逻辑。
- 迁移只执行一次；以后新增和重置密码均使用管理员填写的明文值。

## 登录逻辑

登录服务查询启用账号后，直接比较请求密码与数据库密码：

```text
请求密码 == sys_user.password_hash
```

比较不做 trim，因此密码内部或两端的字符按实际保存值匹配；新增和重置入口会先 trim，以避免管理员误输入首尾空格。登录失败继续返回统一的“用户名或密码错误”，不暴露账号是否存在。

## 前端交互

- 用户模块的新增按钮只对管理员显示，并在事件处理层再次校验角色。
- 用户列表的修改按钮只对管理员显示或启用。
- 新增用户表单显示必填“初始密码”。
- 修改用户表单显示可选“重置密码”，并提示“留空表示不修改”。
- 表单保存后立即清空密码输入状态，不把密码写入列表数据或浏览器持久化存储。

## 后端请求与字段存在性

用户请求增加 `password` 字段，并沿用现有 JSON 字段存在性机制：

- 新增用户必须出现 `password` 且值非空。
- 修改用户缺少 `password` 或值为空时保持原密码。
- 修改用户提供非空 `password` 时更新密码。
- 任何非管理员只要调用用户新增或修改接口，均在数据校验和写入前被拒绝。

## 错误处理

- 非管理员写入用户：`仅管理员可管理用户账号`。
- 新增账号未填写密码：`初始密码不能为空`。
- 其他用户名重复、非法角色、版本冲突沿用现有错误处理。
- 密码不得出现在 API 响应、异常消息或应用日志中。

## 测试

### 后端

- 迁移将所有现有账号密码统一改为明文 `123`。
- 迁移后的管理员可用 `123` 登录，旧 BCrypt 值不能登录。
- 管理员可用简单密码新增账号，新账号可立即登录。
- 管理员重置密码后新密码可登录、旧密码失效。
- 修改账号时不提交或留空密码，旧密码保持不变。
- 新增账号缺少或空密码被拒绝。
- 财务和普通用户新增、修改或重置账号均被拒绝且不产生部分写入。
- 用户列表和用户写入响应不包含密码。

### 前端

- 管理员新增表单显示必填初始密码。
- 管理员修改表单显示可选重置密码及留空提示。
- 非管理员不能看到或触发新增、修改用户操作。
- 新增 payload 包含密码；修改留空时不包含密码；填写时包含新密码。
- 密码字段使用 `type="password"`，保存后组件销毁或清空。

## 明确风险

明文密码会被数据库管理员、数据库备份读取者以及取得数据库访问权的人直接看到。本设计按用户明确要求实施，不增加加密、哈希、首次登录改密或密码复杂度规则。

## 非目标

- 不增加首次登录强制修改密码。
- 不增加用户自行修改密码或找回密码。
- 不增加密码复杂度、过期时间、失败锁定或密码历史。
- 不在页面显示现有密码。
