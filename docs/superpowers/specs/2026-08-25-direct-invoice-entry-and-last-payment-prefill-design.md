# 订单与采购直接发票入口设计

## 目标

让销售订单和采购单可直接维护发票，并在新增发票时带入最近一笔业务登记金额。财务复核继续以同一张业务单据下的发票记录为准。

## 入口与命名

- 所有当前显示为“维护发票”的操作统一改为“发票”。
- 订单管理的每个销售订单增加“发票”操作。
- 采购管理的每个实际采购单增加“发票”操作；采购建议不显示该操作。
- 财务管理保留行内“发票”操作。
- 不增加按单号模糊搜索或独立发票管理页面。每个入口只操作当前行对应的业务单据。

## 发票弹窗

- 弹窗头部展示业务类型和业务单号，说明当前发票关联目标。
- 从销售订单进入时，新增发票的含税金额默认填入该订单最后一笔登记收款的原始金额。
- 从采购单进入时，新增发票的含税金额默认填入该采购单最后一笔登记付款的原始金额。
- 从财务管理进入时，按该行的业务类型与业务 ID 使用同样的默认金额规则。
- 默认金额只在新增表单为空时填充，用户可修改。保存后仍保存用户最终填写的金额。
- 没有任何收款或付款记录时，金额保持为空，不写入零金额。
- 默认值取最近登记记录的原始金额，不取财务复核后的确认金额；发票录入不因财务复核而改变初始建议值。

## 财务复核

- “资金与发票复核”中的发票表始终保留原发票号码列。
- 发票已经复核时，表格同时展示财务确认号码；待复核时，将原号码作为可编辑确认号码的初始值。
- 表格继续显示原金额、确认金额、状态和备注，让财务能对照一张业务单据下的每张发票。
- 没有发票记录时显示空状态，而不是空白表格。

## 数据与接口

- 复用现有按 `SALES` / `PURCHASE` 和业务 ID 读取、保存、删除发票的接口。
- 前端在打开弹窗时额外读取该业务单据的资金记录，并按登记时间倒序选择最新一笔；后端不新增跨单据搜索接口。
- 订单与采购行数据必须提供业务 ID 和业务单号；财务行沿用现有业务 ID、业务类型和业务单号。

## 测试

- 列表组件测试覆盖订单、实际采购和财务行展示“发票”按钮，采购建议不展示。
- 发票弹窗测试覆盖关联业务单号显示，以及用户可以覆盖默认金额后保存。
- 应用级测试覆盖从订单和采购入口打开的关联类型、业务 ID 与默认金额。
- 复核弹窗测试覆盖有发票时显示原发票号码与确认号码。
