# 实时首页看板设计

## 目标与范围

为 GMT 进销存系统增加首页看板，放在左侧菜单第一行并作为登录后的默认页面。首页集中呈现订单、产品库存、采购、发货和售后经营状态，支持最近 7、30、90 天趋势切换，并通过 3D 供需态势观察异常产品和关联业务。

## 导航与页面结构

- 新增模块键 `dashboard`，菜单名称为“首页”，位于客户管理之前。
- 登录成功且 URL 未指定模块时默认进入首页。
- 首页是工作型驾驶舱，不显示新增或导入按钮。
- 页面从上到下包含：关键指标、趋势区域、全宽 3D 供需态势、异常产品清单。
- 点击异常产品的业务入口可跳转到订单、库存、采购或售后模块，并携带可用于列表搜索的关键词。

## 关键指标

首页快照至少包含：

- 今日订单数量与今日销售金额。
- 待确认收款订单、等待齐货订单、等待发货订单。
- 库存缺口产品数量及总缺口数量。
- 待登记付款采购单。
- 处理中售后单。
- 数据库健康状态和快照生成时间。

所有指标都来自同一次后端快照，不由前端分散请求。

## 趋势与异常明细

- 趋势接口支持 `7`、`30`、`90` 天，默认 `30` 天。
- 每日趋势包括订单数量、销售金额、采购数量、发货数量和新增售后数量；无数据日期补零。
- 异常产品按需求、库存和供应三类返回，字段包括产品 ID、客户料号、型号、产品编号、实际库存、在途数量、未发货数量、供需余量、缺口数量和关联业务数量。
- 异常清单默认显示 10 条，按缺口绝对值降序。

## 实时推送

- 使用 Server-Sent Events，端点为 `GET /api/dashboard/events`。
- 客户端建立 `EventSource` 后立即收到 `snapshot` 事件。
- 订单、采购、库存、导入和售后写操作提交成功后发布看板变更事件；推送层合并短时间内的重复事件并重新生成快照。
- 服务端定期发送心跳，浏览器断线后依靠 EventSource 自动重连。
- 前端连接中断时保留最后一次快照并显示“正在重连”；恢复后清除提示。
- 普通 REST 快照与趋势接口保留，供首次加载、手动刷新和测试使用。

## 可视化

- ECharts 绘制订单、金额、采购、发货和售后趋势。
- Three.js 绘制不套装饰卡片的全宽 3D 供需场景，包含需求、库存和供应节点及节点之间的流动粒子。
- 节点大小反映业务规模；正常为中性灰绿色，预警为琥珀色，缺口为红色。
- 鼠标悬停显示节点摘要；点击节点筛选下方异常清单。
- 场景支持拖动旋转和有限缩放，在 `prefers-reduced-motion` 下停止持续动画。
- Canvas 初始化失败时回退为可点击的二维供需指标，不阻断首页使用。

## 技术边界

- 前端新增 `echarts` 和 `three`，不手写图表或 3D 引擎。
- 后端使用 Spring MVC `SseEmitter`，不引入 WebSocket 或 CDC 基础设施。
- 汇总 SQL 使用现有业务表和状态，不变更已有业务数据结构；仅在确有查询需要时增加索引迁移。
- SSE 推送只发送看板快照，不包含敏感个人或财务明细。

## 测试与验收

- 后端测试覆盖快照统计、7/30/90 天补零趋势、异常排序、SSE 首次事件和变更事件。
- 前端测试覆盖首页默认导航、菜单顺序、快照渲染、周期切换、断线状态、3D 节点筛选和业务跳转。
- 生产构建后使用 Playwright 在桌面与移动视口检查布局。
- 对 Three.js Canvas 执行非空像素检查，确认场景已渲染；验证动画、点击和缩放不会遮挡其他界面。
- 部署后验证 REST 快照、SSE 连接、数据库健康状态及运行页面。
