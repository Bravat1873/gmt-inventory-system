# 订单明细库存与产品图片设计

## 目标

在订单管理的新建和编辑弹窗中，销售人员选择产品后，能够在同一条订单明细中立即看到产品主图、实际库存和可用库存，降低选错产品或超出可用库存下单的风险。

## 范围

- 订单明细新增“图片”和“库存”展示。
- 图片使用产品主图；没有主图时显示统一占位状态。
- 库存按 SKU 汇总全部仓库：
  - 实际库存：`SUM(actual_quantity)`。
  - 可用库存：`SUM(actual_quantity + in_transit_quantity - locked_quantity)`。
- 库存信息只读，不改变订单保存参数、现有校验或库存分配规则。
- 不新增图片上传入口，不调整库存计算规则。

## 后端设计

扩展现有 `GET /api/orders/skus` 返回结构，在每个 SKU 选项中增加：

- `primaryImageId`：产品主图 ID；无主图时为 `null`。
- `actualQuantity`：全部仓库实际库存汇总；无库存记录时为 `0`。
- `availableQuantity`：全部仓库可用库存汇总；无库存记录时为 `0`。

查询以 `sku` 为主表，通过预聚合库存子查询和主图子查询关联，保证每个 SKU 只返回一行，避免产品存在多仓库或多图片时产生重复选项。主图沿用现有产品图片读取接口，不在 SKU 列表中传输图片二进制。

## 前端设计

扩展 `OrderSku` 类型以接收三个新字段。订单明细在“物料编号”后增加：

- “图片”列：选中产品后展示约 56×56 的主图缩略图；未选择产品或无主图时显示紧凑占位框。
- “库存”列：分两行显示“实际 X”和“可用 Y”；未选择产品时显示 `—`。

数据随现有产品选项一次加载。切换产品时，图片和库存由当前 `skuId` 对应的 SKU 数据同步更新，不额外发起逐行请求，因此不存在明细切换时的异步竞态。横向滚动容器继续承载所有明细行，新增列不改变弹窗整体滚动方式。

## 异常与边界

- 没有库存记录：实际库存和可用库存均显示 `0`。
- 没有主图：显示“暂无图片”，不显示破损图片图标。
- 图片加载失败：隐藏失败图片并回退到占位状态。
- 可用库存为负数时保留真实负值并使用醒目样式，便于识别超额锁定。
- 编辑历史订单时也按当前库存显示，不把库存快照写入订单明细。

## 测试

- 后端 API 测试验证多仓库库存汇总、主图 ID、无库存/无图片默认值，并确保每个 SKU 只返回一行。
- 前端组件测试验证选中 SKU 后显示主图、实际库存和可用库存；无图时显示占位状态。
- 运行后端完整测试、前端完整测试和生产构建。
- 重启服务后验证前端、后端 HTTP 200，并使用已登录页面检查订单明细展示。
