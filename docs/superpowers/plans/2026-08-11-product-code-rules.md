# Product Code Rules Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add user-maintained product-code mappings, generate unique codes such as `BR_P90HGT60WPZE`, make customer codes nullable and non-unique, and rename material-code terminology throughout the system.

**Architecture:** Store eight categories of code mappings in one normalized table and reference them from `sku`. A focused backend generator is the only authority for formal product codes; existing products receive stable `OLD_******` codes. Existing business foreign keys remain `sku.id`, while query, import, and UI contracts expose both `productCode` and the renamed `customerCode`.

**Tech Stack:** MySQL 8/Flyway, Java 21/Spring Boot/JdbcTemplate, JUnit 5/MockMvc, Vue 3/TypeScript/Vitest, existing CSS component system.

## Global Constraints

- Formal format is `品牌代码_系列代码颜色代码锁体代码联网代码渠道代码运营主体代码语言代码`.
- Product codes are generated by the backend, read-only in the UI, uppercase, and globally unique.
- All eight mappings are required before converting an `OLD_******` product to a formal code.
- Customer codes are nullable and non-unique; business relationships continue to use `sku.id`.
- All logged-in users can read and write mappings in the first release.
- Referenced mappings cannot be deleted or recoded; disabling them preserves historical display but removes them from new selections.
- Existing unrelated dirty worktree changes must not be reset, overwritten, staged, or committed.
